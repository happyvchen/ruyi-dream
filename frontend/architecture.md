# Frontend Architecture

## 产品形态

前端默认是一个面向普通业务用户的“拍摄任务工作台”，不是 AI 参数控制台。当前 `user` 和 `admin` 共用工作台与任务链路，user 三步、admin 四步；后续 admin 增量模块必须建立在完整 user 工作台之上，保证 admin UI/UX 大于等于 user。

后台与 admin 主流程（user 隐藏姿势选搭，将其并入最终成片内的拍摄准备）：

```text
AI 摄影棚导入主推款 -> AI 智能选搭 -> 姿势选搭 -> 最终成片 -> 生成记录复盘
```

`一键成片` 是工作台顶部主操作，用于把上述步骤自动串联到最终成片。它不引入新的前端状态模型：页面仍通过 `GenerationTask.status`、active 指针和各阶段 artifact 渲染，自动流程只显示一条轻量进度。

导入主推款阶段处理图片、货号和轻量服装信息；其它阶段可在右侧任务摘要填写当前步骤要求后重新执行。界面始终使用服装、拍摄和电商语言，不把该输入称为 prompt。

## 前端路由

前端使用浏览器 History API 做轻量路由，不额外引入路由依赖。URL 用来表达可恢复位置，React state 继续承载临时交互状态。

当前路由为 `/studio`、`/studio?task={taskId}`、`/library`、`/model`、admin-only 的 `/prompt-maintenance`、`/records?task={taskId}`。进入 `/studio` 默认恢复最近一次拍摄任务，并将 URL 替换为 `/studio?task={taskId}`；只有用户点击 `新建拍摄任务` 后才显示空白拍摄任务页面。用户点选某个历史任务进入 `/studio?task={taskId}` 时，按 URL 恢复指定任务。当前拍摄任务和记录详情写入 URL，可在刷新或分享后恢复；导入中未保存的本地文件和临时面板状态仍只保存在 React state。

左侧侧边栏的展开 / 收起是本机使用偏好，不进入 URL。首次访问且没有偏好记录时，桌面宽度默认展开，小屏宽度默认收起，并在没有用户偏好时随断点变化自动同步；用户手动展开或收起后写入 `localStorage`，刷新和切换路由都优先尊重该偏好。

登录后前端读取 `/api/auth/session` 返回的 `role`。`admin` 在保留全部 user 路由和工作流的基础上额外看到 `姿势库`、独立姿势选搭与 `Prompt 维护` 入口；普通 `user` 不展示配置入口。品牌边界、AI 打标字段、选搭规则、拍摄导演规则和下游生成规则都通过 Prompt 维护配置。

主推款导入和搭配服装导入在前端先进入待创建清单：散图合并为一套；一个货号文件夹作为一套；一个上级文件夹递归扫描后按最底层图片目录拆成多套；拖入多个货号文件夹时按同一规则拆分。文件选择器不提供选择 N 个文件夹，批量处理通过选择一个上级文件夹或拖入多个文件夹完成。主推款最多 8 张、搭配服装最多 6 张；待创建清单与已创建对象未达上限时都在图片列表末尾显示统一的虚线加号卡。

搭配服装库使用互斥视图：默认显示服装库列表、筛选、分页和批量管理；列表模式采用固定高度三段式面板，工具条在上、卡片内容区按容器宽度响应式排版并独立滚动、分页条固定在面板底部。分页数量不按视口自动计算，固定提供 `24 / 48 / 96 套`并默认 24 套；生成记录同样使用固定分页，提供 `20 / 50 / 100 行`并默认 20 行。进入 `导入搭配服装` 后只显示导入面板、待导入清单和导入任务进度，不把列表继续拼在导入面板下方。批量导入使用两阶段流程：先逐套导入并创建服务端 `StylingGarment` 草稿记录，全部导入 / 保存完成后，再提交标签识别。导入入口支持连续批次；已入库服装未满 6 张时可从详情图片列表末尾继续添加。

主推款导入和搭配服装导入复用同一套轻量导入任务机制。导入任务状态由后端 `upload_sessions` 持久化，前端在进入 `AI 摄影棚` 或 `搭配服装库` 时分别拉取按创建时间倒序的历史窗口和完整活跃状态窗口，再对已知活跃 session 按 ID 精确轮询，避免较早但仍在运行的任务因历史分页而消失。切换左侧页面不应让导入状态从用户视野中无声消失；运行中的导入任务可以在对应页面继续显示，也可以在全局轻量提示中显示数量和阶段。只有仍在浏览器直传文件、刷新会中断本地 `File` 流时，前端才使用 `beforeunload` 二次确认；图片已经保存为业务草稿、进入 AI 识别或其它后端可恢复阶段后，不阻止用户刷新或切换页面。

搭配服装导入记录与服装库的 `导入批次` 筛选共同读取后端 `upload-session-batches` 聚合结果，保持名称、货号数、默认可见范围和首次导入时间倒序一致。浏览器 `localStorage` 中的导入任务只用于文件授权、导入执行和断点恢复，不再决定历史导入记录、筛选枚举或排序。选择导入批次后，前端把稳定 `uploadBatchKey` 交给服装列表接口精确过滤，不再把批次货号拼接到关键词搜索；没有产出服装的失败批次仍保留枚举，并显示专用空状态。

导入记录行直接使用 upload session 返回的 `importOutcome`、`targetSummary` 和 `historySummary`。`importOutcome` 决定主状态和批次当前失败数，`targetSummary` 决定货号、正式封面、正式图片数和 `当前可选搭 / 当前识别失败 / 当前已归档` 等副状态；`historySummary` 只用于表达曾失败后成功的 `已恢复`。前端不得用当前服装库分页结果作为导入记录的唯一关联源，也不得让 `localStorage` 中的旧 `blob:` 预览覆盖已完成会话的正式媒体。底层 `upload_sessions.status = FINALIZED` 仅表示业务对象已创建，不能直接渲染成普通用户最终状态。

部分失败按业务对象局部处理：批量主推款导入以拍摄任务为单位重试，搭配服装导入以货号为单位重试。成功项保留，失败项回到可操作清单或进度卡，展示 `重新导入`、`重新识别`、`删除后重来` 等明确动作，不要求用户整批重传。

## 状态分工

- Server state：`StylingGarment`、`GenerationTask`、默认模特、生成 attempts、已创建的导入任务和最近导入结果。
- Client state：当前页面、尚未开始导入的本地文件草稿、当前浏览器直传进度、loading/error。
- Local preference：侧边栏展开 / 收起偏好存入 `localStorage`，由 React state 读取后驱动当前渲染。
- 当前使用 React local state；后续数据流复杂后再考虑引入 React Query。

## 组件/区域

- AI 摄影棚 admin 四步卡片（user 隐藏姿势选搭，显示三步）：导入主推款、AI 智能选搭、姿势选搭、最终成片。已执行任务编辑主推款图片、排序或服装信息时，前端先进入待确认草稿，不立即替换当前生效素材或清理后续成果；用户确认后再提交影响后续阶段的变更。
- AI 摄影棚右侧任务摘要在 `一键成片` 上方固定一个始终展开的用户输入模块：选搭、分镜和成片步骤编辑当前步骤要求。所有输入都有保存按钮，保存后只作为下一次执行草稿，不改变任务状态。
- 搭配服装库：导入服饰、列表搜索、标签摘要、打标状态、详情抽屉、归档。
- 搭配服装详情抽屉：完整展示 AI/生效/人工/官方标题/元信息标签；底层模型调用过程事实只向 admin 展示。
- 模特与背景页：所有登录用户查看默认模特及一张整组共享背景；普通 user 只读并可打开统一大图检查器，admin 额外拥有模特图片和背景图片的维护能力。
- Prompt 维护页：admin 维护品牌分段和各阶段 Prompt；普通用户不可见；右侧预览工具保持常开，只提供刷新预览和保存。
- 生成记录页：任务列表、任务详情与最终成片展示；旧分镜资产只读兼容。
- 搭配服装库和生成记录的搜索、筛选、计数与批量操作共用响应式工具条规则：宽容器内优先同排，空间不足时按容器宽度自然换成多行，所有动态出现的批量按钮必须保持可见、可点击且不遮挡其它控件。搜索框允许粘贴多个货号或关键词，按空格、中英文逗号、中英文句号、中文顿号和换行拆分，默认任一关键词命中即展示；少量关键词保持单行输入，大量关键词显示批量搜索摘要，点击后用 portal 浮层 textarea 编辑，避免被工具条空间和滚动容器裁切。
- 导入记录、搭配服装库和生成记录通过 `BulkSelection` 共享复选框、Shift 范围和矩形相交框选逻辑。DOM 的 `data-select-id` 表达用户可见的选择目标，不强制等于后端业务 ID；生成批次等聚合目标在指针松开后异步解析为任务 ID，成功后原子提交，失败则回滚目标高亮并保留原选择。页面只负责提供可见目标与业务对象的适配关系，不复制选择算法或临时改变控件样式。
- 导入记录、搭配服装库和生成记录通过统一归档组件共享安全归档、取消归档、影响预检、彻底删除确认和危险状态交互。页面层只保留一个可见入口：单条统一显示 `归档`，批量显示 `归档 N 项`，不因活动、已归档或部分归档状态改变入口名称；弹窗接收可用 action 列表并用单选项分流，选择彻底删除后才展示影响范围和名称确认。页面只注入对象名称、各 action 的目标数量、删除范围文案和资源 API；不得复制归档弹窗、额外暴露删除按钮或让已归档对象必须恢复后才能删除。
- 搭配服装彻底删除不反向删除历史生成任务。影响预检把 `referencingTaskCount` 展示为“会保留但来源显示已删除”的历史引用，不纳入删除数量；媒体数量只表示引用检查后实际会释放的文件。任务详情收到 `sourceAvailable = false` 的选搭快照时只渲染删除占位，不展示旧货号、服装卡或失效图片。

## 生成记录语义

前台“生成记录”和 AI 摄影棚“最近任务”使用同一套 `GenerationTask` 列表口径：任务从草稿创建开始进入列表。混合批次与单次任务的列表及摄影棚默认恢复使用 `GET /api/generation-record-workspace`，单次任务列表使用 `GET /api/generation-records`，详情使用 `GET /api/generation-records/{task_id}`。`event_logs` 仍保留为后端审计/排查信息，但不作为普通用户的生成记录主视图。

AI 摄影棚“最近任务”、生成记录、搭配服装库和搭配服装导入记录等顶层业务对象列表，统一按首次导入 / 创建时间倒序展示；状态推进、打标完成、修改名称或替换图片不改变列表位置。同一时间按业务 ID 倒序稳定兜底。批次内任务、商品图片、模特参考图和最终成片等具有明确业务顺序的子列表继续保持批次顺序、人工排序或镜头顺序。

AI 摄影棚轮询当前 `GenerationTask` 时，右侧“最近任务”中对应任务必须同步更新状态和缩略图摘要，但不能因为状态变化重新排序。当前任务详情和最近任务行使用同一次任务更新结果做 upsert，避免主内容区显示已完成而最近任务仍停留在旧状态。

AI 摄影棚右侧“最近任务”使用 `/api/generation-records` 分页加载，滚动到列表底部时继续取下一页，并在底部显示已显示数量、总数、加载中或已触底提示。最近任务行点击直接进入 `/studio?task={taskId}` 恢复工作台状态。

右侧栏使用 `任务摘要 / 最近任务` 临时 Tab 状态：默认摘要；任务切换和新建任务后回到摘要；最近任务列表保留在独立 Tab 面板中，因此不会被摘要内容挤出可视区域。Tab 状态不进入 URL。

生成记录列表的行主体负责查看详情；行尾恢复按钮按任务状态显示 `查看进度`、`再次生成` 或 `继续生成`，点击后只跳转到 AI 摄影棚并恢复任务，不直接触发任何生成接口。

生成记录的归档与导入记录、搭配服装库使用同一交互契约：单条任务的 `归档` 和批量模式的 `归档 N 项` 都打开统一管理弹窗；行内和详情区不额外提供取消归档或彻底删除。批量模式允许活动和已归档任务混合选择，弹窗按实际可操作对象分别提供归档、取消归档和彻底删除选项。运行中的任务只参与下载等只读操作，不计入归档。任务影响预检、归档、取消归档和彻底删除按后端每批 100 条限制自动分片；分片算法避免产生尾部单条批次，以保持批量确认短语语义一致。确认弹窗在请求完成前保持打开并锁定重复提交；首批失败时保留当前选择和输入供重试，部分分片成功时刷新列表、清空旧选择并提示用户重新选择剩余记录。

生成记录支持批量下载成片：复用行勾选状态，点击 `下载成片 N 项` 先调用导出预检；所选任务成片全部完整时直接触发浏览器下载 zip，存在未完成/失败镜头时弹窗列出明细，提供 `全部下载`（缺失项写入压缩包内清单.txt）、`仅下载完整任务` 和取消。下载通过临时 `<a>` 指向 `GET /api/generation-task-exports/archive` 触发，浏览器原生接管进度；AI 摄影棚成片阶段提供单任务 `下载全部成片` 入口，复用同一接口。

AI 摄影棚右侧“最近任务”也支持批量下载：标题旁 `批量下载` 开关进入选择模式，行首出现勾选框（生成中的任务不可选，选择模式下点行切换勾选而非恢复任务），操作条显示已选数量并触发与生成记录页相同的预检、弹窗和下载流程；下载开始或退出开关后清空选择。选择状态是临时交互状态，只存 React state，不写 URL。

## 媒体与轮询

前端按展示尺寸选择图片档位：

- 货号列表、历史列表、素材卡片、结果网格使用 `thumbUrl`。
- 弹窗查看和详情页大图使用 `previewUrl`。
- 下载、导出、AI 输入和必要质检才使用 `originalUrl`。

后端返回的是稳定 `/api/media?...` 路径，组件不应在轮询中主动替换未变化图片的 `src`。如果同一对象 key 没变，应保留现有 URL，避免浏览器重复解码和重绘。

图片缓存使用浏览器原生 HTTP cache，由后端通过 `/api/media` 的 302 响应和对象存储响应头控制。前端不实现 IndexedDB、Service Worker、Cache Storage 或 OPFS 图片缓存；这些机制会增加权限隔离、容量清理、Blob 生命周期和登出残留复杂度，不作为当前图片体验优化路径。前端不得为绕过缓存给图片 URL 添加时间戳、随机数或轮询版本参数；只有 object key 或 variant 变化时才更新 `src`。

AI 摄影棚首次打开获取完整详情；运行或自动排队期间轮询 `/api/generation-tasks/{id}/status`，合并状态、五图进度和当前阶段。只有 `detailRevision` 变化或进入终态才重新读取详情。批次成员状态由同一协调器更新，不再用独立列表定时器。

前端可用本地临时 `AIOperation` 补足用户刚点击后的即时反馈，但本地 operation 必须带当前 `taskId`，只能渲染到所属任务。任务从后端刷新到非运行中且无 `autoRunTarget` 后，应清理该任务的本地 operation。任务详情只携带各步骤最新一条摘要；展开时通过步骤分页接口按实际 attempt 数量和时间倒序读取历史，不按 owner 合并重试调用。历史调用列表仅 admin 展示和访问，user 使用任务级业务状态与成片数量。每条 admin 技术详情入口通过 taskId + attemptId 精确读取对应 attempt，并在关闭弹窗后恢复触发按钮焦点。被替代链路的历史终态可以复盘，但其遗留运行态不得冒充当前任务仍在执行。

## API 分层

前端只通过 `src/api.ts` 调用后端，不在组件中散落裸 `fetch`。API 契约以 `../backend/api_guideline.md` 为准，领域字段以 `../backend/domain_model.md` 和 `src/types.ts` 对齐。

Docker Compose 部署时，前端镜像构建阶段会把 `PUBLIC_BACKEND_URL` 写入 `VITE_API_BASE_URL`。如果部署域名、端口或反向代理路径变化，需要重新构建前端镜像：

```bash
docker compose up -d --build frontend
```

前端容器只提供静态资源，不代理 API；浏览器直接访问 `PUBLIC_BACKEND_URL`。

## 百兆带宽 P0 实现

- `src/lib/polling.ts`：单个调用完成后才安排下一次；任务/导入默认 2 秒，无变化 30/60/90 秒后改为 5/10/15 秒，加 0–20% 抖动。比较时忽略 `updatedAt` 等心跳时间；隐藏标签页或离线时暂停并取消在途 GET，恢复后立即检查；连续失败按 5/10/20/40/80/120 秒退避（另加抖动）。
- 同文件的 `useSilentRefresh` 统一素材库、服装详情、生成记录和模特背景的可见性与取消规则；列表空闲每 30–36 秒检查版本，存在可见运行条目时以 5–6 秒起步，长期不变退避到 15–18 秒。只调用 `/api/collection-revisions/{scope}`；版本变化后才读取当前筛选、分页或已展开详情，成功后记住版本，失败继续重试。进入导入视图暂停隐藏素材列表；服装详情有未保存图片编辑时暂停更新。摄影棚最近任务采用同一版本检查与间隔规则，只在最近任务 Tab 可见时执行。
- 自动检查不改变 loading/error 状态，不插入更新提示、不淡化或禁用现有列表；响应与现有 JSON 相同则保持引用，不主动更换图片 URL。首次读取、用户翻页/筛选/重新加载继续保留明确加载和错误反馈。
- `src/api.ts`：GET 接受 `AbortSignal`；页面离开只取消页面级只读请求，解析 JSON 后再次检查取消状态和 URL。应用级初始化跨页面继续，各项独立写回；退出登录、角色变化或卸载时由应用 signal 取消。初始化发起后若已切页，不再执行旧路由恢复。列表筛选与详情选择还有资源 token，阻止旧响应覆盖。写接口、PUT 和上传确认不随页面取消。
- `src/lib/uploadQueue.ts`：全标签页共享 PUT 队列，默认 2 路；相同 object key 合并在途 PUT，相同上传 session 合并执行；网络/429/5xx 最多重试 2 次，1/2 秒退避并加抖动。UI 区分等待上传、上传中、保存处理及业务终态。
- `src/components/MediaImage.tsx`：IntersectionObserver 零预取边距，lazy + async + low priority。所有可见图片自动加载，不设置依赖点击/滚动恢复的累计配额；离屏图片保持本地透明占位，进入可视区后加载且不因再次离屏清空 src。换图独立重置可见性与失败状态。检查器主图单独加载当前 preview，没有 original 预取。
- 列表和卡片统一 thumb；检查器先 preview，“1:1 原图”显式更换 src。换图恢复 preview；派生图缺失显示“预览暂不可用”，仍允许用户显式打开原图。下载始终指向 original/download。
- 任务列表 summary 仅有 cover thumb；五图进度使用 `progress.completed/total`，打开任务再获取成片详情。
- 主推款单次/批量导入完成仅在原导入组件仍挂载、导航代次与 URL 均未变化时切换当前任务；离开后继续保存，不能覆盖当前页面或 URL。
- 上传配置 `UPLOAD_CONCURRENCY=1..3`（默认 2）经 Vite/镜像构建注入；修改后需重建前端。不要再增加调用点自己的 PUT 并发池。

## 渐进加载体验补齐

- `MediaImage` 在原有可视区加载策略内维护每个 source 的加载/成功/失败状态，统一稳定图框、占位与同 URL 手动重试。`onOpen` 提供独立的查看覆盖按钮，重试按钮与其同级，避免按钮嵌套；导航按钮内的装饰缩略图设置 `retryable={false}`。
- `ImageAssetCard`、`AssetThumb`、成片网格、记录图片与模特封面复用该状态，不再在父组件用失败标记卸载图片，保证重试入口持续可用。加载/失败状态只影响图片展示，不改变业务状态。
- `LibraryPage`、生成记录页复用 `ListLoadFeedback` / `ListSkeleton`，首次显示静态骨架，刷新保留旧内容；失败提示按是否仍有可见条目区分。手动重试沿用现有 GET、取消 signal 和资源 token，不引入新请求缓存。
- `ImageLightbox` 内的 `LightboxPicture` 按当前图片身份隔离状态。预览加载时用本图 thumb 过渡，原图加载时保留本图已成功加载的 preview，切换图片后重置；资源重试通过重新挂载同 URL 的 img 完成。
- 此轮不调整首屏优先级、零预取边距、初始化恢复时序或轮询策略，不新增依赖；具体体验与验收以 `../design/03_ux_guide/user_uiux.md` 第 10 节为准。

姿势库采用与搭配服装库相同的搜索、筛选、列表面板、卡片、分页、导入清单和详情抽屉组件/样式。数据单元为一图一姿势，批量图片及文件夹按图片逐项入库；详情使用单图替换接口，替换不自动调用 AI。
