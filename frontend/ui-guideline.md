# Frontend UI Guideline

## 核心原则

- 用户看到的是拍摄任务，不是 AI 管线。
- 默认只展示：主推款、搭配服装、分镜预览、最终成片、生成记录。
- 普通用户界面不展示底层模型名称、调用参数、请求快照、返回快照和调试 JSON。
- 当前 `user` 和 `admin` 展示同一套普通拍摄工作台。后续技术人员入口只能作为 admin 的增量模块追加，不能削减普通工作台能力。
- 全局视觉统一、控件层级和 PC 桌面页面改造以 `../design/03_ux_guide/ui_ux_unification_plan.md` 为审核稿；实现时只改变 UI/UX，不改变业务逻辑、后端 API、任务状态机或 provider 调用时机。

## 页面布局

当前 0.1.0 采用分工明确的工作台：

1. `AI 摄影棚`：上传主推款，完成智能选搭、分镜预览和成片生成。
2. `搭配服装库`：导入和管理真实配角服装，导入后系统默认打标。
3. `数字模特`：只读展示当前默认模特。
4. `Prompt 维护`：admin-only 维护品牌分段、AI 打标、AI 选搭、三类分镜预览和三类生成成片 Prompt。
5. `生成记录`：查看从草稿开始的历史拍摄任务、入参信息、选搭、预览和结果。

后续如果为 admin 接入数字模特维护、品牌模板、技术详情和系统配置，应保持 admin UI/UX 大于等于 user：admin 仍能完整完成普通拍摄任务，再额外看到技术模块。

所有主 Tab 页面使用固定高度工作台布局：页面外层和浏览器 `body` 不承担滚动；标题、导航和侧栏保持在当前视口内。每个页面必须把可增长内容放入明确的内容区、列表区或详情区，内容超出时只在该区域内部滚动，并同时允许必要的竖向滚动和横向滚动。导入清单、缩略图轨道、记录列表、Prompt 编辑区、模特图片区等都不能依赖页面整体滚动来露出被裁切内容。

`搭配服装库` 使用互斥的 `服装库列表` / `导入搭配服装` 两种模式。默认只展示列表和筛选工具；点击导入后只展示导入面板、待导入清单和导入任务进度，不在同一内容区下方继续展示服装列表。导入中保留进度面板，任务完成或失败后再允许返回服装库列表。

`Prompt 维护` 是唯一配置入口，不进入普通用户拍摄工作台。页面只做 Prompt 槽位编辑、保存和本地预览；预览不触发模型调用。品牌边界、标签字段口径、AI Stylist 规则、分镜图位规则和 Image-2 生成约束都写入对应 Prompt 正文。

## UI 语义

前台核心对象统一叫 `主推款`、`搭配服装` 和 `拍摄任务`。`搭配服装` 是会真实出现在最终图里的配角服装，不叫素材包。

推荐：

- 页面入口：`搭配服装库`
- 列表对象：`搭配服装`
- 上传动作：`导入搭配服装`
- 单张图片：`服饰图片`
- 计数：`N 套`、`N 张图片`

避免：

- 用 `图包`、`素材包`、`货号图包` 作为当前库页主语义。
- 让普通用户看到或编辑 prompt、provider 参数、模型名称、调用快照或人工标签 JSON。

搭配服装详情：

- 列表卡只显示标签摘要，详情抽屉展示完整 `AI 识别标签`、`生效标签`、`人工业务标签`、`官方标题信息` 和 `标签元信息`。
- 标签详情只展示业务可读字段和值，不展示原始 JSON。
- 底层打标调用详情、请求参数、prompt、图片输入元数据、返回结果和失败信息不进入普通用户界面。
- `TAGGING_READY` 显示为 `待复核`，并允许重新识别标签；仅 `READY` 表示可进入选搭。

上传预览和已保存素材的服装图片卡片必须保持一致：

- 所有图片选择、拖放、文件夹导入、待导入清单添加和替换入口统一接受静态 JPG/JPEG、PNG、WebP、HEIC/HEIF 和 AVIF，不向用户暴露各页面不同的格式能力。
- 使用统一的卡片边框、缩略图比例、文件名排版和删除按钮位置。
- 展示文件名、图片尺寸、文件大小。
- 不展示“主参考/参考图/正面图/3D 图”等图片角色标签。
- 默认第一张图片作为封面，该规则在说明文案中提示，不作为用户需要维护的字段。

上传和导入入口必须符合以下交互规则：

- 支持多张散图、一个货号文件夹、一个包含多个货号的上级文件夹，和拖入多个货号文件夹。
- 文件选择器不提供“选择 N 个文件夹”；批量处理通过选择一个上级文件夹或拖入多个文件夹完成。
- 对上级文件夹递归扫描，把最底层图片目录识别为一套；上级文件夹名默认作为批次名，最底层图片目录名作为货号 / 任务名。
- 待导入清单支持继续添加，新内容按同一规则追加；创建任务或入库后不再提供继续添加图片或文件夹。
- `AI 摄影棚` 顶部 `选择图片` 是用散图新增一款待创建项，顶部 `选择文件夹` 是按文件夹识别并新增待创建项；只有卡片内 `新增图片` 用于补充当前货号图片。
- 超过 15 张的暂存套标红，文案说明正式上传 / 保存时会自动剔除超出上限的图片。
- 混合目录结构和被忽略的非图片文件必须给出可读提示，不静默猜测。

图片展示按实际 UI 尺寸选择档位：

- 列表、卡片、缩略图和结果网格使用 `thumbUrl`。
- 弹窗预览和详情大图使用 `previewUrl`。
- `originalUrl` 只用于下载、导出、AI 输入和必要质检，不作为普通列表或弹窗默认图片。
- 轮询刷新时，如果图片对象 key 未变化，不主动替换 `src`，避免浏览器重复下载、解码和重绘。

## 文案规则

使用：

- 首图
- 全身
- 半身
- 背面
- 侧身
- 局部
- 拍摄方案
- 分镜预览
- 成片
- 生成
- 重新生成
- 设为最终
- 取消最终
- 下载成片

避免默认展示：

- prompt
- task package
- Image 2 参数
- provider
- Gemini / Image-2 / fal / toapis 等底层模型或供应商名称
- seed
- adapter

允许普通用户填写的内容只使用业务语言，例如 `智能选搭要求`、`分镜预览要求`、`成片要求`。不要把这些输入标成 prompt，不展示权重、role、system/user、temperature 等模型参数。

避免混用：

- `默认方案` / `确认方案` / `拍摄方案` 指同一业务概念时，统一写 `拍摄方案`。
- `重生` / `重新预览` / `重新生成分镜` 指重新生成动作时，统一写 `重新生成` 或 `重新生成分镜预览`。
- `最终图` 不写成 `候选`、`可用`、`已确认` 等内部评审状态。

## 控件语义

相同业务语义必须使用同一套控件，不按页面临时拼样式。

- 任务型按钮统一使用 `task-action`：用于推进拍摄任务或恢复拍摄任务的关键动作，视觉与 `一键成片` 保持一致，包括蓝青渐变、白字、生成类图标、稳定高度和最小宽度。包括 `一键成片`、`继续一键成片`、`重新一键成片`、`AI 智能选搭`、`重新选搭`、`生成预览`、`重新生成分镜预览`、`生成成片`、`重新生成成片`、`继续生成`、`再次生成` 和 `查看进度`。
- 管理型按钮统一使用 `management-action`：用于日常整理、上传、导入、保存、下载、批量管理、归档和恢复归档，使用中性描边样式，不抢占任务推进按钮的视觉优先级。
- 危险型按钮统一使用 `danger-action`：只用于彻底删除、删除关联文件或其它不可逆破坏数据的确认动作。
- 图标型控件用于图片卡角落、关闭、替换、移除和查看大图等局部操作，保持固定尺寸，不与任务型按钮竞争视觉层级。
- `AI 摄影棚` 顶部提供 `一键成片` 主按钮；步骤内仍保留各阶段生成按钮。任务运行中或存在自动推进意图时，所有生成按钮和单张重生禁用，只保留取消。
- 一键成片运行时使用轻量阶段进度条展示 `智能选搭 / 分镜预览 / 成片`，不展示 provider、prompt 或任务包。
- 页面顶部的统计、筛选和计数使用统一的工具条或指标条；筛选项、搜索框和批量操作必须按容器宽度自适应换行，大屏优先同排，小屏允许多行展示，不得通过隐藏、遮挡或挤出可点击区域解决空间不足。
- `显示已归档` 使用筛选控件；货号数、任务数、已策划数使用指标卡或计数胶囊。
- `归档` 是日常整理动作，使用中性次级样式。
- 只有会删除文件、删除关联记录或不可逆破坏数据的操作，才使用危险样式。
- 归档/删除弹窗底部操作统一右对齐：取消为次级按钮，默认归档为主按钮；勾选删除关联文件后，主操作才升级为危险按钮。
- 结果图卡默认只保留 `重新生成`、`设为最终` / `取消最终`。不展示候选、可用、需精修或质量原因选择。
- 列表批量选择是当前页临时状态。`全选本页` 只选择当前可见页；切换页码、筛选条件、归档视图或每页显示数量时清空选择，批量按钮只统计当前可见且可操作的项目。

## 生成记录

生成记录以任务为主，不以事件日志为主，并与 AI 摄影棚的最近任务保持同一套列表口径。

最近任务、生成记录和搭配服装库默认按创建时间倒序展示；状态变化不应让列表项跳到顶部。

列表展示：

- 缩略图
- 货号
- 任务状态
- 完成张数
- 最终图数量
- 重新生成次数
- 创建时间

生成记录的列表行主体用于 `查看记录详情`，不使用小眼睛按钮。行尾恢复任务按钮按状态显示：运行中为 `查看进度`，已完成为 `再次生成`，未完成且非运行中为 `继续生成`。这些按钮只跳转到 `/studio?task={taskId}` 并恢复 AI 摄影棚状态，不直接触发生成、重试或 provider 调用；真正的生成动作仍由摄影棚中的阶段按钮或一键成片按钮确认。

详情展示：

- 本次入参信息
- 每个图位的当前输出
- 每个图位的当前成片和重新生成记录
- 分镜预览与最终成片

`AI 摄影棚` 的任务摘要只展示当前拍摄任务的紧凑概览，并在 `一键成片` 上方按步骤显示用户要求模块：选搭、分镜和成片步骤显示当前步骤要求；上传主推款阶段不显示额外文本输入。用户要求模块始终展开，不提供收起入口。模块不放解释文案，标题与摘要字段对齐，输入框优先保证足够高度，保存按钮使用小尺寸。所有输入都有保存按钮，保存只影响下一次执行，不改变当前任务状态。完整历史在 `生成记录` 页面查看；点击记录可通过 URL 恢复指定拍摄任务详情。

已执行任务修改主推款图片、排序或服装信息时，前端先维护待确认草稿，不立即替换当前已生效素材，不立即清空选搭、分镜或成片。用户点击 `确认修改` 后才提交变更，并用业务文案提示后续成果会失效但历史记录保留。

`AI 摄影棚` 上传主推款与 `搭配服装库` 导入搭配服装使用同一套归组清单和图片卡 UI，包括散图合并、文件夹归组、图片顺序、文件名/尺寸/大小展示和角落删除入口。差异只放在业务字段和参考图上限：AI 摄影棚清单在货号右侧提供 `服装信息` 输入，搭配服装库维护配角服装入库字段。

`AI 摄影棚` 右侧 `最近任务` 是轻量恢复入口，不承担记录详情复盘。最近任务每行展示主推款缩略图、任务名、状态和创建时间；状态靠左、创建时间靠右，不展示最终图完成数。点击整行恢复对应任务。列表应在右侧栏内部支持滚动加载全部任务，底部显示总数、已显示数量、加载中和已触底提示，避免用户误以为只能看到前几条。

如需内部排查 prompt、任务文本、provider 摘要，应放在后台或工程调试入口，不进入普通用户前台。

`Prompt 维护` 以 PC 桌面端为生产目标，始终展示右侧预览工具，不提供 `预览工具` / `收起预览工具` 按钮；页面主操作保留保存和刷新预览。小屏幕只保留基础可访问布局，不作为当前产品体验验收范围。

## URL 规则

支持：

```text
/studio
/studio?task={taskId}
/library
/model
/prompt-maintenance
/records
/records?task={taskId}
```

核心对象切换要同步 URL，方便刷新恢复和分享。弹窗、折叠、hover、临时上传草稿不进入 URL。

## 状态规则

| 状态 | 用户文案 |
|---|---|
| `DRAFT` | 待确认 |
| `CONFIRMED` | 已确认 |
| `QUEUED` | 排队中 |
| `RUNNING` | 生成中 |
| `SUCCEEDED` | 已生成 |
| `FAILED` | 生成失败 |

| 业务状态 | 用户文案 |
|---|---|
| `READY_FOR_STYLING` | 待选搭 |
| `STYLING_READY` | 已选搭 |
| `PREVIEW_READY` | 分镜预览完成 |
| `FINAL_PARTIAL` | 部分完成 |
| `COMPLETED` | 已完成 |

## 高级设置

高级设置可以包括：

- 尺寸增强
- 拍摄角度微调
- 补充要求
- 风格参考说明

这些设置默认折叠，不阻塞默认生成流程。
