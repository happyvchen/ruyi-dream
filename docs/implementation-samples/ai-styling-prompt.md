# AI 选搭 Prompt 实施样例

当前采用 `styling-plan-v2` 精简最终方案契约。两份参考正文必须成对使用：

- [主推款图片挑选/排序](../../backend/prompt_templates/hero_image_selection.txt)：填入 `assembly.hero_image_selection`，只负责商品图挑选与顶层响应说明。
- [AI 选搭](../../backend/prompt_templates/ai_styling.txt)：填入 `assembly.ai_styling`，负责选搭任务、业务边界、品牌与动态输入以及唯一输出契约。

正文是可维护参考，不是系统初始化默认值或代码 fallback。运行时仍只读取数据库 Prompt 配置。应用前备份两个槽位并成对保存，搭配支持 v2 的后端；不要改写历史请求和结果。品牌信息仍引用 `segment.brand_info`。

## 提示词设计

先说明任务与判断顺序，再限定事实来源、用户要求优先级及配饰边界；随后输入品牌、服装信息、用户要求和完整标签库；最后给出唯一字段契约及短核对项。避免在挑图 Prompt 重复选搭 Schema，也不将镜头、姿势或光线职责混入选搭。

仅输出最终结果。完整套装或可独立穿着时无需额外搭配；没有合适商品时空搭配。`empty_reason` 区分自身完整、库内无合适商品和用户要求不搭配；不能把缺少上衣或下装的情况说成完整穿着，也不能通过配饰文本编造服装。

## 本地验证

检查真实拼接路径中没有未解析占位符；校验三类空搭配、合法及非法商品编码、穿法与配饰传入下游、图位族路由和旧协议兼容。主观选搭质量需要经用户授权的真实案例对比才能确认，本地 mock 不证明审美提升。
