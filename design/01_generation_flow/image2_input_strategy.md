# Image 2 输入职责拆分与提示词策略

## 1. 核心原则

Image 2 的输入同时包含大量图片和文本时，应该遵守一个原则：

`图片决定事实，文本决定任务。`

在当前 Lily 商品图场景里，这条原则进一步收敛为：

`服装素材图是唯一商品事实源；Prompt 不复述具体服装事实，只授权图片事实并声明保真边界。`

更完整的产品原则是：

`预处理层负责理解，策划层负责决策，Image 2 负责生成。`

Image 2 不应承担以下职责：

- 每次重新推理 品牌调性
- 判断什么鞋包符合目标品牌
- 临场发明模特 pose
- 临场决定组图镜头
- 用长文本修正服装比例
- 通过审美词猜测商品结构

这些职责应在 Image 2 之前完成，并以结构化任务包的形式传给 Image 2。

也就是说：

- 服装长什么样，尽量由服装图片决定。
- 模特长什么样，尽量由模特头部图片决定。
- 目标品牌的拍摄调性，尽量由真实成片参考图决定。
- 文本不要重复描述图片里已经明确的细节，尤其不要默认写入 Gemini 自动识别出的具体颜色、扣子数量、刺绣位置、口袋数量、面料名称等服装事实。
- 文本只负责告诉模型：这些图片分别是什么角色、哪些信息必须保留、当前要生成哪张图、哪些边界不能越过。

如果文本过度描述图片内容，容易出现冲突：

- 图片是轻 A 字，文本写 A-line，模型可能夸大成大摆。
- 图片是短裙，文本写 dress，模型可能自动变长。
- 图片里鞋履很轻松，文本写通勤，模型可能生成老气职业鞋。
- 图片是某个具体模特，文本写 young female model，模型可能只保留年龄和风格，不保留身份。

所以后续产品应该把“输入图片”和“提示词文本”的职责拆开。

## 2. 输入图片的职责

### 2.1 服装图片负责商品事实

服装图包决定：

- 服装品类
- 颜色
- 面料质感
- 版型
- 领型
- 袖型
- 裤长/裙长/衣长
- 下摆宽度
- 口袋、纽扣、拉链、开衩、褶皱
- 图案、印花、条纹
- 正面和背面结构
- 局部细节

文本不要重复写成一大段服装描述，也不默认把 VLM/Gemini 识别出的具体服装事实写进 Image 2 prompt。推荐只写事实授权和保真范围：

`服装素材参考图是唯一商品事实来源。请直接依据服装参考图还原服装的品类、颜色、面料、版型、结构、比例、长度、门襟、扣位、口袋、刺绣、领型、袖口和细节质感。不要根据文字自行改造、补全或简化服装。`

不推荐默认写：

- 具体颜色名，例如“卡其色”“米棕色”
- 具体扣子数量或扣位
- 具体刺绣文字、刺绣位置或 logo 形状
- 具体口袋数量
- 具体面料名称
- 任何未经人工确认、只由 Gemini 自动识别得到的服装事实

例外：用户人工确认的“硬保真点”可以进入 prompt。例如用户明确标记“必须保留左领 LILY 刺绣”或“必须保留双排扣结构”。这类信息是业务约束，不是模型猜测。

### 2.2 模特头部图负责身份

模特头部图包决定：

- 同一张脸
- 脸型
- 五官
- 发型
- 刘海
- 发色
- 耳饰
- 头部角度
- 表情边界

文本只需要说明：

- 当前使用哪个头部角度
- 必须保持同一身份
- 不允许重新生成另一个相似风格的模特

### 2.3 品牌真实成片负责品牌调性

真实成片参考图决定：

- 光线
- 背景
- 构图
- 人物占比
- pose 语法
- 鞋包和配饰的自由度边界
- 商品优先级
- 画面克制程度

文本只需要说明：

`品牌真实成片参考图定义姿态、鞋包、配饰、光线、背景和构图边界。不要复制某一套非本货号服装。`

### 2.4 九宫格预览图负责导演分镜

预览阶段生成的 2x3 图不是商品事实来源。它在最终生图阶段只负责：

- 姿势
- 身位
- 景别
- 取景范围
- 背景光线方向
- 服饰搭配方向
- 5 张图之间的视觉节奏

最终生图 prompt 必须明确：

`九宫格预览图只用于参考姿势、身位、景别、构图、背景光线和搭配方向；不得作为服装商品事实来源。服装事实始终以服装素材参考图为准。`

### 2.5 Pose 参考图负责身体动作

Pose 参考图决定：

- 身体朝向
- 重心
- 手臂位置
- 腿部姿态
- 头部朝向
- 走动感或静态感

文本只需要指派：

- 参考哪张 pose 图
- 当前生成的镜头目的是什么
- 哪些动作不能夸张

## 3. 文本提示词的职责

文本只做 6 件事：

1. 标注图片角色
2. 定义当前镜头任务
3. 指定保真优先级
4. 指定生成边界
5. 指定平台输出格式
6. 指定禁止项

文本不做这些事：

- 不重新描述服装图里已经清晰可见的款式、颜色和细节。
- 不把 Gemini 自动识别的具体服装事实当成最终生图事实写死进 prompt。
- 不用 `fashionable`、`premium`、`modern` 这类泛审美词替代 品牌模板。
- 不用 `A-line`、`short dress` 这类可能导致比例漂移的抽象词单独控制裙长和裙摆。
- 不让 Image 2 自己判断“适合 目标品牌的鞋子”。
- 不让 Image 2 自己决定本款该拍哪几张。

## 4. 图片角色设计

每次生成单张图时，建议传入以下图片角色。

| 角色 | 是否必需 | 决定内容 |
| --- | --- | --- |
| Garment Front | 必需 | 服装正面结构 |
| Garment Back | 视镜头而定 | 服装背面结构 |
| Garment Detail | 建议 | 面料、局部、工艺 |
| Model Head Angle | 必需 | 当前镜头的人脸身份 |
| Preview Contact Sheet | 最终生图必需 | 已确认的姿势、身位、景别、背景光线和搭配方向 |
| Brand Style References | 建议 | 品牌调性、鞋包、pose、构图 |
| Pose Reference | 建议 | 当前镜头身体动作 |
| Previous Approved Output | 可选 | 同一组图一致性 |

### 4.1 预览与最终生图的图片顺序

| 阶段 | 输出目标 | 图片顺序 | 数量规则 | 图片事实职责 |
| --- | --- | --- | --- | --- |
| 预览 | 一张 2x3 Contact Sheet | 图1~M：模特身份图；图(M+1)~N：服装素材图 | 总数 <= 10；模特最多 4 张；服装图使用剩余额度 | 模特图锁定人物身份；服装图锁定商品事实；本阶段没有九宫格输入 |
| 最终生图 | 5 张单图，每张单独调用 Image-2 | 图1：已确认九宫格预览图；图2~M：模特身份图；图(M+1)~N：服装素材图 | 总数 <= 10；九宫格固定 1 张；模特最多 4 张；服装图使用剩余额度 | 九宫格只定义导演分镜；模特图锁定人物身份；服装图是唯一商品事实源 |

预览阶段详细规则：

- 图1~N：模特身份参考图在前，服装素材参考图在后。
- 模特身份图最多 4 张，按数字模特 UI 当前显示顺序。
- 服装素材图按服装素材 UI 当前显示顺序补齐剩余额度。
- 输出：一张 2x3 Contact Sheet。

最终生图阶段详细规则：

- 图1：已确认的 2x3 九宫格预览图。
- 图2~5：数字模特身份参考图，最多 4 张，按 UI 当前显示顺序。
- 图6~10：服装素材参考图，使用剩余额度，按 UI 当前显示顺序。
- 每个最终图位单独调用一次 Image-2；5 次调用共享同一九宫格、同一批模特图、同一批服装图和同一个公共 prompt 前缀。

如果总数超过 fal `image_urls <= 10` 限制，应优先保证：

1. 九宫格预览图
2. 模特身份图
3. 服装素材图

当前 MVP 不做服装素材角色分类，因此服装图按 UI 顺序截取。后续可增加“生成用参考图勾选/排序”，由用户把最关键的服装图放入前 5 张。

## 5. 文本结构模板

正式 prompt 统一使用中文，并尽量短。最终生图推荐使用“图片事实授权型”结构：

```text
任务：
生成一张 电商 AI 模特图，当前图位为 {shot_id}：{shot_role}。
本次只生成这一张单图，不要生成九宫格、拼图、文字说明、水印或边框。

图片角色：
- 图1 是已确认的 2x3 分镜预览图，只用于参考第 {shot_id} 格的姿势、身位、景别、构图、背景光线和搭配方向；它不是服装商品事实来源。
- 图2~{model_end} 是同一位数字模特身份参考图，用于锁定脸型、五官、头型、发型、刘海、气质和身体比例。
- 图{garment_start}~{garment_end} 是同一服装货号的素材参考图，是唯一商品事实来源。

优先级：
1. 服装素材参考图是最高优先级商品事实来源。
2. 模特身份参考图是最高优先级人物身份来源。
3. 九宫格预览图只决定导演分镜，不覆盖服装事实。
4. 当前图位脚本决定景别、取景范围、姿势和身位。

当前图要求：
{framing / angle / product focus}

服装保真：
请直接依据服装素材参考图还原服装的品类、颜色、面料、版型、结构、比例、长度、门襟、扣位、口袋、刺绣、领型、袖口和细节质感。不要根据文字自行改造、补全或简化服装。

可选比例约束：
{model measurements / garment measurements / target wearing length if provided}

禁止：
不要换脸、不要改变发型、不要改变服装结构、不要改变服装长度和比例、不要新增服装细节、不要按九宫格里的低清细节重画服装、不要生成文字、水印或 logo。
```

该模板不默认写入具体颜色、扣子数量、刺绣位置、口袋数量、面料名称等服装事实。具体事实由服装素材图主导。只有用户人工确认的“硬保真点”才可作为具体文字约束进入 prompt。

## 6. 反例：不推荐的冗余文本

不推荐：

```text
black sleeveless A-line dress, round neckline, blue striped ruffle, short skirt, soft fabric, fashionable, modern, high quality...
```

原因：

- 容易把图片里的具体比例变成抽象语义。
- `A-line` 可能放大裙摆。
- `short skirt` 可能不够精确。
- `fashionable` 可能引入不需要的造型变化。

推荐：

```text
服装参考图是商品事实来源。保持服装真实长度、下摆宽度、荷叶边露出比例、面料和结构。
```

在新的最终生图规则下，更推荐写成：

```text
服装素材参考图是唯一商品事实来源。请直接依据服装参考图还原服装结构、比例、长度、面料和细节质感，不要根据文字自行改造或补全。
```

如果有尺寸，再补：

```text
穿着长度约束：黑色主体下摆位于膝上 {x} cm；条纹荷叶边露出高度为 {y} cm。
```

## 6.1 fal API 入参映射

Image 2 的产品任务包会转换为 fal GPT Image-2 edit queue 入参。

```json
{
  "prompt": "中文 Image 2 prompt",
  "image_urls": ["上传到 fal 后的参考图 URL"],
  "image_size": "auto",
  "quality": "high",
  "num_images": 1,
  "output_format": "png",
  "sync_mode": false
}
```

`image_urls` 的来源：

- `task_package.imageInputs[].objectKey`：对象存储中的参考图 key。
- `task_package.imageInputs[].url`：后端生成的短期预签名 GET URL。
- `task_package.imageInputs[].providerUrl`：已经可被 fal 读取的 URL。

提交前，系统会先把参考图上传到 fal，再把 fal 返回的 Image URLs 作为 `image_urls` 传给 Image-2。

预览任务遵守 fal `image_urls <= 10` 限制：先按数字模特 UI 当前显示顺序取最多 4 张模特图，再按服装素材 UI 当前显示顺序使用剩余额度补服装图，总数最多 10 张。

最终生图任务也遵守 fal `image_urls <= 10` 限制：图1 固定为已确认九宫格预览图，随后传入最多 4 张模特图，再用剩余额度传入服装素材图。每个生成任务会保存对象 key、图片角色、预签名 URL 和 provider URL 的映射。

当前配置：

```env
GPT_IMAGE2_PROVIDER=fal
FAL_KEY=...
GPT_IMAGE2_QUEUE_URL=https://queue.fal.run/openai/gpt-image-2/edit
GPT_IMAGE2_QUALITY=high
GPT_IMAGE2_OUTPUT_FORMAT=png
```

正式生成使用 fal queue，不使用长时间同步 HTTP 等待。点击生成后，后端提交 queue 并保存 `request_id`、`status_url`、`response_url`、`cancel_url`，再由后台 poller 查询状态。

## 7. 产品功能映射

产品上应把输入拆成以下模块：

- `服装事实图组`
- `模特身份图组`
- `品牌调性参考图组`
- `Pose 参考图`
- `可选尺寸参数`
- `单张镜头任务`
- `禁止项`

前台用户看到的是结构化配置，不是长 prompt。

底层 prompt 由系统自动合成，而且尽量短。

## 8. 与前置推理/策划层的关系

Image 2 的上游应该有一个 `组图策划器`。它可以由推理模型、视觉模型、规则引擎和模板检索共同组成。

组图策划器负责：

- 从服装图包生成商品事实卡。
- 判断品类和高风险点，例如裙长、裤长、下摆宽度、细节易丢失。
- 从 品牌模板库中选择同品类、同图位、同季节感的真实参考图。
- 选择鞋包和配饰的风格边界，而不是让 Image 2 随机选择。
- 为每张图绑定 Pose 模板、头部角度、镜头范围和构图规则。
- 生成每张图的短文本任务。

Image 2 只接收策划器组装好的 `单张生成任务包`：

```json
{
  "shotId": "02",
  "shotRole": "侧身全身",
  "imageInputs": [
    "garment_front",
    "garment_back",
    "garment_detail",
    "model_head_left45",
    "dress_style_refs",
    "pose_dress_side_walk_01"
  ],
  "constraints": {
    "identity": "以 Face-01 头部图为身份事实",
    "garment": "以服装参考图为商品事实",
    "styling": "以 连衣裙模板为鞋包和姿态边界",
    "proportion": "如有尺寸参数，以尺寸参数控制裙长和下摆"
  },
  "prompt": "任务：生成一张 电商 AI 模特图，当前图位为 02：侧身全身。图片角色：服装参考图是商品事实来源；模特头部图是身份事实来源；品牌真实成片参考图定义姿态、鞋包、配饰、光线、背景和构图边界。禁止换脸、改变服装结构、改变服装比例、生成文字、水印或 logo。"
}
```
