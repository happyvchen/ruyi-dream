# Image-2 输入策略

当前成片模型为 GPT Image-2.5 Sunburst（`gpt-image-2.5-sunburst`），只负责视觉生成：最终成片按五个固定镜头逐张生成 1:1 成片。Image-2 不负责选搭、不负责判断商品品类、不负责动态规划镜头。

## 参考图角色

| 角色 | 用途 |
|---|---|
| `model_identity` | 数字模特身份、脸型、五官、发型轮廓、肤色和气质事实源 |
| `hero_garment` | 主推款商品事实源 |
| `styling_garment` | 被选中搭配服装商品事实源 |
| `shot_background` | 整组统一背景图，是 `image_urls[0]`；只提供场景与光线，不约束景别、机位、裁切或人物尺度 |
| `shot_pose` | 当前镜头独立选定的姿势原图，提供具体动作、神态与表现风格；不提供身份、服装、背景或光线，不覆盖镜头 Prompt 的景别与构图。发送前按镜头景别预裁切（上装镜头 1 保留上部 0.78、镜头 2 保留 0.45、镜头 3 保留 0.40），否则全身姿势图会把每个镜头都拉回全身构图 |

## 最终成片输入

成片输入：整组统一背景、当前镜头姿势参考、数字模特参考图、主推款参考图、选中搭配服装参考图、品类固定成片 Prompt、`StylingPlan` 造型摘要和成片用户要求。

## 图数预算

Sunburst 每次最多传入 14 个 `image_urls`，按以下顺序组装：

| 输入 | 数量 | 取图方式 |
|---|---:|---|
| 共享背景 | 1 | 整组冻结的背景 |
| 当前姿势 | 1 | 当前镜头冻结的姿势，沿用景别预裁切 |
| 模特首图 | 1 | “模特与背景”中排序首张，独立传入 |
| 模特四宫格 | 1 | 前四张（包含首张）依次放入固定 2×2 宫格 |
| 主推款 | 最多 6 | 冻结顺序的前六张，各自独立传入 |
| 搭配款 | 最多 4 | 按已选服装及其图片的冻结顺序展平，合计取前四张，各自独立传入 |

五个镜头使用相同的模特与商品来源顺序，不再按镜头跳选主推款图片。商品图片不拼板，保留独立输入的有效细节。模特首图提供大图身份事实，宫格补充身份视角；宫格包含首图，不以第五张替换它。模特不足四张时使用已有图片，空格留白，不复制填满；宫格等比适配白底，不裁切或拉伸来源图。

新输入版本冻结当时排序前四张模特图片，后续维护不会改变已冻结来源。历史版本仅有一至两张时按已有快照组装，不从当前配置补图；已有结果的重生优先复用原任务包。缺少商品图时不重复补足数量。attempt 快照记录每个输入的角色、原始 objectKey、宫格来源、裁切策略和输入策略版本。

不使用遮罩或 `mask_url`。attempt 快照记录全部输入职责、来源顺序和结果集冻结的背景与姿势资产。

镜头5的正背双视图、中央细缝和中央3:4竖向裁切安全区由成片 Prompt 明确控制，背景图不承载人物布局。


## API易参考图传输尺寸策略

API易通道在冻结的几何处理完成后，以尽可能保留该参考图的像素尺寸为优先原则；历史裁切、宫格等几何策略由各自冻结版本决定，传输压缩不改变其业务职责。

- [API易 VIP 图片编辑文档](https://docs.apiyi.com/api-capabilities/gpt-image-2-vip/image-edit)写明“推荐单张 ≤10MB”，这是建议值，未明确单图及整组的硬性字节上限。工程目标保守取单张 10,000,000 字节，不设整组字节预算。
- 单张未超过目标：保留完整字节、像素尺寸和元数据，不设2048等固定长边上限，也不受其他图片体积影响。
- 单张超过目标：先在原尺寸尝试无损编码优化，再在原尺寸尝试有限的质量压缩（WebP 95、90、85）；只有以上方式仍超目标时才等比缩小。不放大，不覆盖存储原图。编码格式允许在 PNG/JPEG/WebP 支持范围内变化，透明通道与颜色配置需保留。
- 任何本地处理失败在提交前报错；明确的上游体积拒绝原样记录并停止，不自动付费重试；超时归为提交结果未知，不能据此推断体积上限。
- 上传审计记录处理前后字节数、尺寸、处理方式、质量和 SHA256，策略版本为 `apiyi_multipart_v2`。历史 manifest 不回写。

既有实测成功的单图约14.53MB、13张整组约51.84MB只能证明当次请求被接受，不能作为官方最大值或长期承诺。实现无需额外付费探测这些边界；其他 provider 的体积策略保持独立。

API易取图优先使用存储中的静态 PNG/JPEG/WebP 原文件，绕过导入阶段默认8000长边的标准化副本；其他导入格式仍使用标准化副本转为支持格式。冻结的裁切和宫格布局继续生效，其他通道的取图方式不变。
