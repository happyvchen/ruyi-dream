# 当前直接成片工作流

## 当前主流程

```text
导入主推款
→ AI 智能选搭（Gemini，输出 selected_files + styling_plan）
→ 姿势选搭（商品图与全库标签初筛即定选，冻结统一背景与五个不同姿势）
→ 最终成片（可选 LLM 提示词整理 → GPT Image-2.5 Sunburst edits，按五个固定镜头并发生成）
```

0.1.0 的生产候选链路不再生成分镜预览，也不存在动态拍摄剧本、`ShootScript` 或 `ShotPlan` 运行 artifact。导演约束由三类固定成片 Prompt 的五个镜头块承担；代码只负责拍摄图位族路由、当前镜头、参考图顺序、选中造型摘要和用户补充要求等动态事实。

详细姿势流程及启用要求见 [姿势库与独立姿势选搭](pose_library_workflow.md)。

## 统一背景与独立姿势

“模特与背景”维护一张整组共用背景，只提供空间、背景颜色/材质、墙地关系与光线方向、柔硬、色温等照明事实。它不提供人物、服装、景别、机位、裁切、站位或人物尺度。五镜头使用同一模特和服装；各自姿势来自姿势库，摄影构图由当前镜头 Prompt 决定。

姿势选搭只进行一次整组初筛，查看主推款、已选搭配和共享背景，结合全库标签和五个已渲染镜头要求直接确定最终姿势，不追加候选姿势原图或调用二次精选。最终五个姿势编号必须不同，无法满足时明确失败。选姿势时冻结背景、成片模板及引用分段，并复用服装选搭的输入版本（含模特）；结果集沿用这些事实。

新选择使用 `shared_background_v1` 标记。历史母版、旧预设接口和已冻结结果集继续保留；旧结果继续、重生使用原快照。历史任务主动重新选姿势后进入统一背景流程。新流程不要求维护15张母版。

镜头5的正背双视图、中央细缝与中央3:4裁切安全区明确写入三类成片 Prompt，不再依赖母版承载。

## Prompt 槽位

最终成片按 `styling_plan.hero_understanding.shot_category_family` 选择三类固定 Prompt：

| 品类族 | Prompt 维护键 |
|---|---|
| 上装、针织、外套、马甲、西装马甲 | `assembly.final_image_top` |
| 裤装、半身裙 | `assembly.final_image_bottom` |
| 连衣裙、连体、套装 | `assembly.final_image_one_piece` |

每类 Prompt 内含5个条件镜头块，明确各镜头景别、视角、裁切、商品表达、人物尺度及镜头5安全区；代码只激活当前块。姿势选搭用同一配置渲染五个镜头要求，最终成片复用冻结配置，不另外维护一套镜头规则。

三个 `assembly.storyboard_preview_*` Prompt 槽位退出运行链路并从 Prompt 维护目录移除。

## 单镜头输入预算

成片继续采用现有 6 个参考图 URL 的输入预算，不因模型升级扩大图数。ToAPIs Sunburst 文档兼容 `image_urls`，Playground 最多选择 6 张参考图。

预算按「少而大」分配：每个角色只送一张事实图，不再把多张商品图拼成多格参考板。拼版在实测中会摊薄单张事实图的有效像素，身份、图案与绒面在拼版里被压掉后模型只能自行编造，表现为“平涂的衣服”和“通用的脸”。

每个镜头按以下顺序组装，不使用同组成片连续性锚点：

1. 整组共用的背景图 1 张，固定为 `image_urls[0]`，只参考环境与光线；
2. 当前镜头姿势参考图 1 张，按镜头预裁切（见下）；
3. 数字模特身份图 1 张；
4. 主推款第 1 张（封面正面）；
5. 主推款第 2 张：正面镜头用细节特写，侧面与背面镜头用背面图；
6. 搭配服装主图 1 张。

总 `image_urls` 不得超过 6。单张来源图直接使用原图。发送 ToAPIs 前只生成运行时传输副本：按 8000 长边、3600 万总像素和 9.5 MiB 安全目标等比规范化，透明底转白底；姿势图额外按镜头裁切（保留上部比例：上装镜头 1 保留 0.78、镜头 2 保留 0.45、镜头 3 保留 0.40，其余镜头与品类不裁切）。裁切只作用于运行时传输副本，绝不覆盖原始商品图、模特图或背景与姿势素材。任务包和 attempt 快照必须记录每个输入的角色、裁切策略、原始来源、结果集冻结的背景与姿势资产及输入策略版本。

姿势参考按镜头裁切的原因：全身姿势图会把每个镜头都拉回全身构图，仅靠 Prompt 文字无法稳定约束景别；把姿势参考先裁到当前景别，实际生成才会落到七分身或上半身近景。

## 生成参数

最终五张均固定使用：

```text
model: gpt-image-2.5-sunburst
size: 1:1
resolution: 2k
quality: high
n: 1
```

请求使用 `/v1/images/generations`；存在 `image_urls` 时进入多参考图编辑模式，不传 `mask_url`。Sunburst 普通版兼容现有小写 `2k`、`image_urls` 和异步任务查询协议，继续使用 URL 返回方式。参数依据：[ToAPIs Sunburst 文档](https://docs.toapis.cn/docs/cn/api-reference/images/gpt-image-2.5-sunburst/generation)。

## 成像质量约束

三个成片 Prompt 都必须使用**正向的摄影真实感要求 + 少量结构性负向约束**，而不是大段“反伪影”要求：

- 光线：主光/补光方向与光比、头发肩线高光分离、背景自主体向画面边缘自然变暗、主体脚下真实落地阴影；不得出现“均匀照明 / shadowless / even lighting”这类抹平光比的措辞。
- 材质：皮肤保留毛孔、细纹、细小绒毛与肤色不均；针织保留绒毛边缘、针脚与罗纹凹凸；梭织保留纱支纹理、自然折痕与垂坠重量；白色面料亮部仍保留纹理，不靠曝光抬白。
- 商品保真：图案的数量、密度、大小比例、朝向与裁切关系逐一对位商品图，不镜像、不重排、不放大；背面按商品图背面的实际图案；不得出现文字、logo、领标、洗标或吊牌；交叠关系（下摆与腰头）、手与包带、两只鞋的跟型必须一致。
- 只保留结构性负向：不要电影调色、不要滤镜、不要颗粒噪点堆叠、不要磨砂或画布质感。

历史版本的表述（“颜色和明暗自然连续、均匀”“材质纹理只来自真实服装本身”“不要胶片颗粒、做旧、磨砂”“避免噪点、云斑、波纹、摩尔纹”）会让成片退化为平光、平涂、塑料皮肤，已从三类成片 Prompt 中移除；`噪音/摩尔纹/色斑` 这类真实印刷或压缩瑕疵改由上游素材和人工验收拦截，不再写成 Prompt 里的“去质感”指令。

该约束只降低生成伪影概率，不能替代对上游输出的人工验收。

## 状态机

```text
DRAFT
→ READY_FOR_STYLING
→ STYLING_RUNNING
→ STYLING_READY
→ POSE_SELECTION_RUNNING
→ POSE_SELECTION_READY
→ FINAL_RUNNING
→ FINAL_PARTIAL / COMPLETED
```

失败统一进入 `FAILED`；取消进入 `CANCELLED`。新任务不再进入 `PREVIEW_RUNNING` 或 `PREVIEW_READY`。历史分镜与历史 attempt 保留只读复盘，不参与新的继续生成。

## 失效关系

- 修改主推款图片：服装选搭、姿势选搭和成片全部失效；
- 重新服装选搭：姿势选搭与成片失效；重新选姿势成功：成片失效；
- 修改背景或姿势图片：不反向修改已冻结的任务，新选姿势使用当时当前生效的背景，结果集复用已冻结的选择；
- 重新生成成片：不反向改变选搭。

`继续一键成片` 复用当前选搭和成片结果集，只重新执行失败、取消或尚未创建的成片槽位；成功槽位保持不变。只有用户明确执行“重新一键成片”时，才重新执行服装与姿势选搭，创建新的结果集。

## 明确不做

- 不提供分镜预览步骤或 API；
- 不保存新的分镜预览表记录；
- 不提供动态拍摄剧本或镜头计划；
- 不让 LLM 重新导演；仅允许按下述规则整理已渲染的成片提示词；
- 不传同组成片作为连续性锚点；
- 不引入自动视觉评分、自动验收或因质量判断触发的自动重生。

## 成片提示词优化

管理员在 Prompt 维护的 `assembly.final_prompt_optimizer` 配置系统规则与启用开关；默认关闭，当前生产默认关闭。

关闭的原因（基于任务 1479 五镜头实测）：整理后的提示词会系统性引入抹除摄影质感的措辞（`shadowless`、`even studio strobe`、`no noise / no moiré / no grain`、`product-mockup`），把“七分身”译成 `three-quarter` 导致景别失控，并把已经写好的商品保真要求缩写掉。相同素材、相同时刻，直接使用固定成片 Prompt 得到的皮肤、针织与光影明显优于整理结果。

重新启用前，必须先把 `prompt_templates/final_prompt_optimizer.txt` 末尾的硬禁止规则保存进配置，并做一轮五镜头实测。

槽位初始化为空，“填入 imagegen 原文摘录”只替换编辑草稿，保存后才生效。建议规则直接摘录 imagegen 的 `SKILL.md`、`references/prompting.md`、`references/sample-prompts.md`，以及 `references/cli.md` 中关于图片编号/角色和重复不变量的两条写法；按来源分组，保留英文原文、各来源内部顺序及所选完整示例，不翻译、不改写、不合并重写条目。覆盖结构、具体程度、合理补充范围、构图、锁定要求、图中文字、多图引用、迭代、商品摄影和换装/局部编辑/合成示例。API 参数、网络配置和无关资产类型不进入优化规则。本应用输入输出协议在末尾单独标明，限定示例仅供写法参考、不得覆盖已确认要求，不与 Skill 原文混写。不随外部 Skill 自动更新。首版复用当前 Gemini 通道，不增加独立模型设置页。

新流程在选姿势时冻结成片模板及分段，创建结果集时冻结优化启用模式与优化规则。启用后，后端渲染五个镜头，将背景、五个姿势、模特与商品参考图实际传入，一次多模态 LLM 调用输出五份完整提示词，不重新选择搭配或姿势。共享图片去重，每镜头保留局部图号与全局附件图号映射，参考板使用与最终生图相同的确定性合成方法。源模板全文交给 LLM，不要求固定标题，不提取或拼接锁定段落。摄影要求与优化方式均由 Prompt 维护。

多模态整理结合可见的商品、身份、动作和背景事实，保留各镜头 Prompt 的景别、裁切、条件与职责，不从姿势图借用身份、服装或背景，不从背景图继承构图。输出使用各镜头原局部图号，不能误用优化请求的全局图片编号。通用示例不能覆盖本应用要求；不编造不可见商品细节，不新增后端内容审查或自动回退。

LLM 只需返回每个镜头的 shotId、optimizedText。后端按镜头读取正文，原样传给 Image-2.5，不进行冲突判断、图片编号检查、占位符检查、长度审核或内容改写，也不要求改动摘要。只处理无法解析响应或无法取得镜头正文的调用错误，不发送空提示词，不自动退回原文。模型调用前保存源任务包和系统规则；调用前失败记录为 PROMPT_PREPARATION_FAILED，不误归类为模型输出错误。

优化的 sourcePackages、系统规则全文、模型、原始返回和错误保存到现有 GenerationAttempt，owner_type 为 generation_result_set；结果集 prompt_preparation_json 保存配置和可复用的最终提示词。图片 attempt 保留原始渲染与实际发送文本，历史 NULL 快照表示原直出链路。

- 普通用户仍为四步，内部显示“正在准备拍摄要求”；管理员可查看优化记录。
- 优化失败可继续重试；生图失败只复用冻结提示词，成功镜头保持不变。
- 单张重生无新增要求时复用；有新增要求时仅重新整理目标镜头，继续使用结果集冻结的商品、模特、模板和图片。
- 已有 provider task ID 的请求优先恢复原请求，不重新优化。
- 取消后不提交新图片请求；若在途多模态调用返回了合法结果，可保存供后续继续复用。
- 运行中的配置修改不影响原结果集；重新选姿势读取当前成片配置，新建结果集读取当时的优化配置。
- “测试优化”由 admin 显式触发，只调用 LLM，保存独立调用记录，不替换任务结果。可选历史图片调用测试单镜头，或历史整组优化调用测试整组。保存、读取、刷新渲染预览均不调用 AI。
