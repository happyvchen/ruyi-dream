# 当前直接成片工作流

## 当前主流程

以下是后台执行链路，admin 保留四步；user 仅显示导入主推款、AI 智能选搭、最终成片。user 点击生成成片后复用自动推进与断点继续，姿势选搭、可选提示词整理统一显示“正在准备拍摄”，无需中间确认。

```text
导入主推款
→ AI 智能选搭（DeepSeek V4.1 Flash，经 ToAPIs，输出 selected_files + styling_plan）
→ 姿势选搭（商品图与全库标签初筛即定选，冻结统一背景与五个不同姿势）
→ 最终成片（可选 LLM 提示词整理 → GPT Image-2.5 Sunburst edits，按五个固定镜头并发生成）
```

0.1.0 的生产候选链路不再生成分镜预览，也不存在动态拍摄剧本、`ShootScript` 或 `ShotPlan` 运行 artifact。导演约束由三类固定成片 Prompt 的五个镜头块承担；代码只负责拍摄图位族路由、当前镜头、参考图顺序、选中造型摘要和用户补充要求等动态事实。

详细姿势流程及启用要求见 [姿势库与独立姿势选搭](pose_library_workflow.md)。

## 统一背景与独立姿势

“模特与背景”维护一张整组共用背景，只提供空间、背景颜色/材质、墙地关系与光线方向、柔硬、色温等照明事实。它不提供人物、服装、景别、机位、裁切、站位或人物尺度。五镜头使用同一模特和服装；各自姿势来自姿势库，摄影构图由当前镜头 Prompt 决定。

姿势选搭只进行一次整组初筛，查看主推款、已选搭配和共享背景，结合全库标签和五个已渲染镜头要求直接确定最终姿势，不追加候选姿势原图或调用二次精选。最终五个姿势编号必须不同，无法满足时明确失败。选姿势时冻结背景、成片模板及引用分段，并复用服装选搭的输入版本（含模特）；结果集沿用这些事实。

新选择使用 `shared_background_v1` 标记。历史母版、旧预设接口和已冻结结果集继续保留；旧结果继续、重生使用原快照。历史任务主动重新选姿势后进入统一背景流程。新流程不要求维护15张母版。

镜头5的正背双视图、中央极细纯白缝与中央全高3:4裁切窗口明确写入三类成片 Prompt，不依赖姿势参考原始版式承载。最终输出保持1:1，裁切窗口为横向12.5%–87.5%，内部内容安全边界为15%–85%；人物中心约33%/67%，衣物、手脚和包完整落在安全边界内。空间不足时整体等比缩小人物并移位，不改变身体比例。 外侧安全留白仍是共享背景的延伸，输入纯白补边不能变为输出白边；中央白缝是唯一的版式例外。优化器须在最终正文中逐项保留画布、裁切窗口、整图百分比、完整轮廓与等比缩小/内移要求，不得概括成“3:4竖幅”或“适当留白”。现有输入补方处理保持不变，竖图补左右、横图补上下，均居中且不拉伸；补方不保证成片安全区。

## Prompt 槽位

最终成片按 `styling_plan.hero_understanding.shot_category_family` 选择三类固定 Prompt：

| 品类族 | Prompt 维护键 |
|---|---|
| 上装、针织、外套、马甲、西装马甲 | `assembly.final_image_top` |
| 裤装、半身裙 | `assembly.final_image_bottom` |
| 连衣裙、连体、套装 | `assembly.final_image_one_piece` |

每类 Prompt 内含5个条件镜头块，明确各镜头景别、视角、裁切、商品表达、人物尺度及镜头5安全区；代码只激活当前块。姿势选搭仅从同一配置的「## 机位&景别」章节渲染五个镜头要求（`runtime.pose_shots`），不传入其他成片正文；最终成片复用冻结的完整配置，不另外维护一套镜头规则。章节必须逐镜头存在且包含有效的条件正文，缺失或重复时在调用前报配置错误，不回退全文。

三个 `assembly.storyboard_preview_*` Prompt 槽位退出运行链路并从 Prompt 维护目录移除。

## 单镜头输入预算

成片每次最多传入 14 个参考图 URL。每个镜头按以下顺序组装，不使用同组成片连续性锚点：

1. 整组共用的背景图 1 张，固定为 `image_urls[0]`，只参考环境与光线；
2. 当前镜头姿势参考图 1 张，沿用镜头预裁切；
3. “模特与背景”排序首张模特图，作为独立大图；
4. 前四张模特图（包含首张）拼成固定 2×2 宫格，作为一张输入；
5. 主推款按冻结顺序取前六张，逐张输入；
6. 所有已选搭配款按服装及图片冻结顺序展平，合计取前四张，逐张输入。

新输入版本冻结排序前四张模特来源；宫格按从左到右、从上到下排列，等比放入白底，不裁切、不拉伸。不足四张时空格留白，不重复填满。历史输入版本不从当前配置补图。五个镜头不再跳选商品图片，商品不足预算时按已有数量传入。详细职责见 [image2_input_strategy.md](image2_input_strategy.md)。

发送 ToAPIs 前只生成运行时传输副本：按 8000 长边、3600 万总像素和 9.5 MiB 安全目标等比规范化，透明底转白底。新结果集保留完整姿势图，不执行固定比例裁切或独立参考图补白成方图；输出景别由镜头 Prompt 控制。宫格保留自身格位与标签区，不另补方，不覆盖原始素材。历史冻结请求仍按其原策略恢复。任务包和 attempt 快照记录每个输入的角色、宫格来源、裁切策略、原始来源、冻结背景与姿势及输入策略版本。

## 生成参数

最终五张均固定使用：

```text
model: gpt-image-2.5-sunburst
size: 1:1
resolution: 2k
quality: high
n: 1
```

请求使用 `/v1/images/generations`；存在 `image_urls` 时进入多参考图编辑模式，不传 `mask_url`。Sunburst 普通版兼容现有小写 `2k`、`image_urls` 和异步任务查询协议，继续使用 URL 返回方式。参数依据：[ToAPIs Sunburst 文档](https://docs.toapis.cn/docs/cn/api-reference/images/gpt-image-2.5-sunburst/generation)。

### 可选 API易通道

`GPT_IMAGE2_PROVIDER=apiyi` 为独立的同步图片编辑 provider：`APIYI_IMAGE_MODEL` 默认锁定 `gpt-image-2.5-sunburst-2026-09-08`（官方转发生产接受 Sunburst/Flare 日期快照；另可显式选择 `gpt-image-2.5-sunburst-vip`），`APIYI_IMAGE_SIZE=2880x2880`（VIP 的 4K Detail 方图档），固定 `quality=max`、`n=1`。使用 `/v1/images/edits` multipart 的 `image[]`，不传 `response_format`、`input_fidelity`，参考图职责、顺序、五镜头并发和冻结版本均沿用现行工作流。

该通道的传输副本独立压缩：单张大于1.5 MB时才以原格式、质量90、长边≤2048等比重编码（不放大小图）；整批超过6 MB时进一步等比缩小。压缩失败的图片回退原图，保留全部参考图并记录无法达标的情况。返回的纯 `b64_json` 在后端解码并保存到现有 S3 媒体，前端复用预览和下载。同步请求最低等待360秒，断连、超时或网关5xx后禁止自动补提；已收结果的保存失败只恢复交付，不重新生成。API易 `max` 和 ToAPIs `high` 分别按各通道协议传输，互不覆盖配置。

## 成像质量约束

三个成片 Prompt 都必须使用**正向的摄影真实感要求 + 少量结构性负向约束**，而不是大段“反伪影”要求：

- 光线：以共享背景实际可辨的方向、柔硬和光比呈现自然体积，不额外指定固定灯位、补光比例或背景渐变；头肩高光和落地阴影只适用于相应区域入画时；不得出现“均匀照明 / shadowless / even lighting”这类抹平光比的措辞。
- 材质：画内皮肤保持自然细节；各商品按原图还原织物组织、毛羽、纹理尺度、光泽和原有压褶；不将微距纹理放大到全身。穿着折痕只随动作、松量、重力和接触受力产生，洗水明暗不变成立体揉皱；白色面料亮部仍保留纹理，不靠曝光抬白。
- 固有色与受光：三类固定成片 Prompt 对主推款和搭配款分别区分真实底色、花色与参考图中的照明、投影、褶皱和反光。仅对商品图支持的纯色区域要求底色均匀、连续，不将受光明暗误生成色斑或雪花状杂色；保留原有印花、提花、色织、混色纱、渐变、洗水及做旧。整件图与微距图分别提供整体质感和组织工艺依据，纹理尺度与当前景别相符；细腻面料保持细腻，原有毛羽和凹凸组织不磨平。优化器将这些适用边界写入每镜头正文，证据不足时保留引用与判断边界，不猜测商品事实。
- 商品保真：图案的数量、密度、大小比例、朝向与裁切关系逐一对位商品图，不镜像、不重排、不放大；背面按商品图背面的实际图案；不得出现文字、logo、领标、洗标或吊牌；交叠关系（下摆与腰头）、手与包带、两只鞋的跟型必须一致。
- 只保留结构性负向：不要电影调色、不要滤镜、不要颗粒噪点堆叠、不要磨砂或画布质感。

历史版本对整幅明暗要求均匀、连续，或笼统消除纹理、做旧与瑕疵的表述存在平光、平涂和塑料质感风险，已从三类成片 Prompt 中移除。当前允许的“均匀、连续”仅限定商品图支持的纯色区域固有底色，不限定成片亮度，不消除真实花色、织纹或光影。真实素材中的噪点、摩尔纹等质量问题仍由上游素材和人工验收拦截，不通过整体去质感解决。本次固有色与受光规则调整尚未经生成对照验证，不能宣称已消除任务 1503 的斑驳问题。

该约束只降低生成伪影概率，不能替代对上游输出的人工验收。

## 状态机

```text
DRAFT
→ READY_FOR_STYLING
→ STYLING_RUNNING
→ STYLING_READY
→ POSE_SELECTION_RUNNING
→ POSE_SELECTION_READY
→ FINAL_RUNNING
→ FINAL_PARTIAL / COMPLETED
```

失败统一进入 `FAILED`；取消进入 `CANCELLED`。新任务不再进入 `PREVIEW_RUNNING` 或 `PREVIEW_READY`。历史分镜与历史 attempt 保留只读复盘，不参与新的继续生成。

## 失效关系

- 修改主推款图片：服装选搭、姿势选搭和成片全部失效；
- 重新服装选搭：姿势选搭与成片失效；重新选姿势成功：成片失效；
- 修改背景或姿势图片：不反向修改已冻结的任务，新选姿势使用当时当前生效的背景，结果集复用已冻结的选择；
- 重新生成成片：不反向改变选搭。

`继续一键成片` 复用当前选搭和成片结果集，只重新执行失败、取消或尚未创建的成片槽位；成功槽位保持不变。只有用户明确执行“重新一键成片”时，才重新执行服装与姿势选搭，创建新的结果集。

## 明确不做

- 不提供分镜预览步骤或 API；
- 不保存新的分镜预览表记录；
- 不提供动态拍摄剧本或镜头计划；
- 不让 LLM 重新导演；仅允许按下述规则整理已渲染的成片提示词；
- 不传同组成片作为连续性锚点；
- 不引入自动视觉评分、自动验收或因质量判断触发的自动重生。

## 成片提示词优化

管理员在 Prompt 维护的 `assembly.final_prompt_optimizer` 配置系统规则与启用开关；默认关闭，当前生产默认关闭。

关闭的原因（基于任务 1479 五镜头实测）：整理后的提示词会系统性引入抹除摄影质感的措辞（`shadowless`、`even studio strobe`、`no noise / no moiré / no grain`、`product-mockup`），把“七分身”译成 `three-quarter` 导致景别失控，并把已经写好的商品保真要求缩写掉。相同素材、相同时刻，直接使用固定成片 Prompt 得到的皮肤、针织与光影明显优于整理结果。

重新启用前，必须先把 `prompt_templates/final_prompt_optimizer.txt` 末尾的硬禁止规则保存进配置，并做一轮五镜头实测。

槽位初始化为空，参考规则仅填入编辑草稿，显式保存后才生效。当前整理规则采用精简的中文职责边界、姿势权限、图号映射及 JSON 输出约定，保留编号映射、可见范围、商品颜色、受力形变和表情复刻约束；通用图片编辑示例不覆盖本项目要求。不随外部 Skill 自动更新。复用当前文本/视觉理解通道（ToAPIs DeepSeek V4.1 Flash），不增加独立模型设置页。

新流程在选姿势时冻结成片模板及分段，创建结果集时冻结优化启用模式与优化规则。启用后，后端渲染五个镜头，将背景、姿势、模特与商品参考图实际传入，不重新选择搭配或姿势。共享图片去重，五个已选姿势按最终生图使用的完整原图合为一张三列两行参考板，格子固定对应镜头 1–5、第六格留空；镜头 5 原有双视图完整保留在第五格。新结果集整组一次调用：共享背景、姿势参考板、模特单图、模特身份宫格、最多六张主推款、最多四张搭配款，满额 14 张附件。异常输入超过通道 16 张保护上限时明确报错，不自动拆批。历史结果集仍按冻结的旧协议分批恢复。每镜头保留最终生图局部图号与优化附件图号、姿势格号映射，模特宫格与姿势来源使用与最终生图相同的方法，新任务不裁切、不额外补方；不同裁切或画布策略不得去重为同一附件。每批完成即保存冻结提示词，后续失败或取消时保留已完成批次，继续时仅整理未完成镜头。源模板全文交给 LLM，不要求固定标题，不提取或拼接锁定段落。摄影要求与优化方式均由 Prompt 维护。

多模态整理结合可见的商品、身份和背景事实；姿势仅保留原图引用、复刻范围和允许变化，不重新设计，也不将图中具体姿态、标签或 direction 改写为动作指令。整理时保留各镜头 Prompt 的景别、裁切、条件与职责，不从姿势图借用身份、服装或背景，不从背景图继承构图。输出使用各镜头原局部图号，不能误用优化请求的全局图片编号。通用示例不能覆盖本应用要求；不编造不可见商品细节，不新增后端内容审查或自动回退。

LLM 只需返回每个镜头的 shotId、optimizedText。后端按镜头读取正文，原样传给 Image-2.5，不进行冲突判断、图片编号检查、占位符检查、长度审核或内容改写，也不要求改动摘要。只处理无法解析响应或无法取得镜头正文的调用错误，不发送空提示词，不自动退回原文。模型调用前保存源任务包和系统规则；调用前失败记录为 PROMPT_PREPARATION_FAILED，不误归类为模型输出错误。

优化的 sourcePackages、系统规则全文、模型、各批请求与原始返回和错误保存到现有 GenerationAttempt，owner_type 为 generation_result_set；结果集 prompt_preparation_json 保存配置和可复用的最终提示词。图片 attempt 保留原始渲染与实际发送文本，历史 NULL 快照表示原直出链路。

- 普通用户显示三步，在最终成片页内显示“正在准备拍摄”；管理员可查看优化记录。
- 优化失败可继续重试；生图失败只复用冻结提示词，成功镜头保持不变。
- 单张重生复用所选版本实际发送的文本和图片；新增要求只附加到该镜头，不重新运行全组优化或读取当前模特配置。
- 已有 provider task ID 的请求优先恢复原请求，不重新优化。
- 取消后不提交新图片请求；若在途多模态调用返回了合法结果，可保存供后续继续复用。
- 取消检查覆盖文本传输重试、图片上传后提交、并发等待后的提交及失败补提；取消后重启时，原执行记录保持取消，旧成片只保留历史，不覆盖新一轮。已经发出的图片请求仍可查询和回传，不承诺撤回上游生成。
- 运行中的配置修改不影响原结果集；重新选姿势读取当前成片配置，新建结果集读取当时的优化配置。
- “测试优化”由 admin 显式触发，只调用 LLM，保存独立调用记录，不替换任务结果。可选历史图片调用测试单镜头，或历史整组优化调用测试整组。保存、读取、刷新渲染预览均不调用 AI。

## 升级后的已有记录

用户在原记录详情查看所有成片轮次与单张版本，不增加“历史入口”。继续生成只处理同组未成功的镜头；单张重新生成使用所选版本的原始商品、模特、选搭与拍摄输入；整组重新生成创建新组，沿用指定组各镜头事实。重新一键成片才重新选搭、选姿势并采用当前工作流，旧轮次持续可见和可下载。

旧版可能只在单张重生时更新了整组 input_version_id，故不能用组指针重建其他镜头输入。迁移优先保留逐次调用证据；缺失事实不得伪造。旧请求不超过当前 14 张上限时保留原输入；超过上限时，前十三张保持独立，后续来源完整组成第十四张标号参考板，同时保存原请求和编号映射；这是传输兼容，不重新选择商品、模特、背景或姿势。该适配的真实视觉质量需单独试生成验收。

已发布图片与执行状态分别保存：失败、取消不会移除旧图，成功发布原子写入图片版本；取消后的迟到输出只保存调用证据，不发布。任务当前输入与选搭输入不一致并非自动认定为损坏；姿势选搭按选搭输入执行，同时比较执行前捕获的任务指针以防并发修改。

## 集成规则与配置生效

三类固定模板与整理器同步维护商品事实、身份/表情、背景/光线和取景边界；固定模板无需依赖整理器开启。现有模特身材资料从对应输入版本渲染到 runtime.model_body_facts，缺失时为空，不读取当前模特档案补齐旧请求。已保存实际任务包、优化正文及单张重生仍优先复用原快照。

整理器在每批已有调用内统一商品结构、相对长度及环境事实，再按可见范围分别编写正文；不声称看到其他批次，跨批次不新增调用或返回字段。该约束仍是提示词软约束，不构成逐字共享事实冻结或视觉验收。

修改当前配置仅影响后续重新选姿势及新建结果集；已有结果集、成功图片、历史标签不回写。参考文件需同步当前生效规则，避免管理员再次填入参考规则时丢失已采纳的修复。

新结果集冻结 `referenceGeometry=original_v1`，不再设置 `referenceCanvas` 或姿势 `providerCrop`；背景、姿势、模特和商品来源保留完整画面与宽高比，优化姿势板也不额外补成方图。宫格自身格位留白、传输等比压缩仍保留。历史结果集缺少此标记时，继续还原旧比例裁切及已冻结的 `referenceCanvas=square_white_v1`；已有请求、标签、成片和原素材不回写。

### 可维护实际消息与过程事实

Prompt 维护中的指令结构与发送结构一致：system 使用优化规则原文；user 使用独立的“成片提示词优化 · 用户消息”模板，仅由占位符接收各镜头 sourcePrompt、局部图号与批内附件编号映射。图片实际附件由传输代码处理，保留去重与冻结分批协议；新任务不裁切、不额外补方。媒体存储路径等审计元数据不注入新调用的 user 文本。

打标／选搭与挑图的组合、格式重问、单张新增要求和旧参考板映射也由明确可维护的模板承载。代码只提供动态事实和执行确定性状态机、数量限制、取消重试等产品规则，不隐藏追加业务指令。成片模板预览展示原始渲染正文；启用优化时该正文是优化输入，真正生图使用模型返回正文，不声称可在调用前预知输出。

调用记录以每批实际输入输出为准。共享配置只保留在后续执行需要的结果集或姿势选择中；每镜头任务包不再重复复制整套配置。已发送正文、原始响应、图片来源及几何处理、版本和 provider 恢复事实继续保留。迁移 089 对历史重复数据自动瘦身，不触发生成，不改变历史结果与重生输入。技术详情按批次配对展示，原始过程 JSON 默认折叠；维护页按历史事实预览不调用 AI。

## 失败镜头的恢复优先重试

失败镜头的“重试”与“继续成片”优先恢复原请求：本地已有输出时补登记；平台已完成时下载原图；仍在排队/生成时继续查询。明确任务不存在、明确可重试的生成失败，或平台确认结果过期且图片不可获取时，才以冻结拍摄输入重新生成该镜头。一次人工恢复最多补提一次，失败后保留记录；查询超时、鉴权或连接配置变化、普通下载故障均不作为“没有结果”的证据。

ToAPIs 的业务编号在发送前持久化，任务 ID 丢失时以原业务编号查询。恢复使用原平台，保存连接范围用于防止配置变化后误查其他账号；历史无平台信息的记录不臆造平台。API易同步接口的 HTTP 请求编号不能代替异步任务 ID：有已保存 base64/输出时只恢复交付；提交未知且没有可查询凭据时，跳过整组继续中的该镜头，提示用户明确选择“重新生成”，可能产生新的费用。

失败镜头默认重试不读取新的成片要求、不重跑提示词优化、不影响成功镜头。显式选择旧图片版本、传入调整要求或选择“重新生成”属于新的生成。人工恢复创建关联原 attempt 的记录，保留失败历史；已有图片版本与取消后的迟到结果仍遵守原子发布保护。

新结果集冻结 `poseInstructionSource=reference_image_v1`，成片和优化器源正文中的 `runtime.shot_pose` 为空。动作与表情仅以姿势原图为依据；缺少标记的历史结果集继续使用原冻结动作协议。完整采用新规则需重新选姿并创建结果集；修改配置不自动重识别标签或重生成历史成片。
