# 姿势库与独立姿势选搭

## 用户流程

新建拍摄任务固定四步：导入主推款 → AI 智能选搭 → 姿势选搭 → 最终成片。一键成片按同一顺序执行。姿势选搭服务已确认造型，不重新选择商品、不生成分镜、不改写五镜头的摄影要求。

姿势库沿用搭配服装库的卡片、搜索、分页、批量选择、图片资产卡、大图检查与归档管理。每个姿势包含名称、稳定业务编号、唯一一张原图、完整 AI 标签和识别状态。一张图片对应一个姿势；散图和文件夹均逐张拆成独立条目，文件夹仅用于批量选择，名称默认取图片文件名（可编辑）。详情只能替换单图，替换后状态回到待识别，已冻结的拍摄历史仍使用原图。旧版多图条目在迁移 077 中保留原图并拆分，首图保留原编号，额外图片获得独立编号；拆分条目需重新识别，历史快照不变。先保存全部条目，再提交识别，失败项可重试；页面切换保留当前浏览器会话中的草稿和已入库编号。刷新页面后已入库条目仍在库中，未上传本地文件需重新选择。

默认只展示未归档姿势，支持关键词、识别状态和归档筛选。只有未归档且 READY、有有效图片的姿势参加选搭。图片变化后回到 DRAFT，旧标签可只读查看，重新识别成功才重新参与选搭。归档不影响历史任务，彻底删除需要影响预检及名称确认；被历史选姿势或调用快照引用的图片保留，最后一个引用清除后才释放文件。

## 从 lily 采用的部分

采用 lily 的标签筛选方法，当前只保留初筛：整组调用一次，查看主推款、已选搭配原图和共享背景，结合全库标签、配饰穿法及从成片 Prompt 渲染出的逐镜头要求，直接确定五个不同姿势。取消二次精选，不发送候选姿势原图；模型不得声称已看过姿势原图或为姿势偷改商品结构、搭配。最终成片仍读取选定姿势原图。

新 Prompt 每镜头直接返回 poseCode、imageId、reason、direction。兼容已保存的旧 Prompt：若仍返回 candidateCodes，直接采用每镜头第一项，唯一图片由冻结库映射，动作说明保留该姿势标签；不重新排序、不搜索替代项、不再次调用模型。首选重复、编号无效或图片不唯一则明确失败。

ToAPIs 每次消息最多 16 张图片。初筛按商品和背景实际来源数量组装：未超限时直接发送原图，超限时把全部来源按顺序合成带编号的参考板，每板最多四张，等比缩放且不裁切，编号置于独立留白区。图片清单记录发送顺序、板内位置与原始商品编号；不截断商品图片或姿势标签，也不由代码替代模型选择姿势。原始清单和实际发送清单同时写入 attempt，参考板仅在内存中组装，不修改对象存储原图。超过参考板容量时在本地明确失败；通道发送前再次校验上限，图片超限错误不自动重试。

保留本项目的先服装后姿势顺序、固定五镜头、S3 媒体与数据库历史。没有迁入 lily 的本地目录存储、服装与姿势组合自由探索、生成后自动视觉验收或自动修图。

## 职责边界

| 输入 | 职责 |
|---|---|
| 主推款、搭配服装原图 | 商品结构和细节事实 |
| StylingPlan | 已确认商品、穿法、品牌与造型方向、品类族 |
| 统一背景图 | 共享空间、背景材质、墙地关系和照明；不限制景别与构图 |
| 姿势库原图与标签 | 可辨动作、表情、接触、受力和执行条件 |
| 姿势选搭 Prompt + 模型 | 基于标签的五镜头初筛定选，输出每镜头选择理由和动作说明 |
| 三类成片 Prompt | 五镜头景别、机位、裁切、商品表达、镜头5双视图及安全区、成像约束 |
| 代码 | 可用范围、编号与图片归属、五镜头覆盖校验、调用、状态与冻结引用；不打审美分、不硬编码动作选择规则 |

每镜头定选一张姿势图，五个镜头必须使用不同姿势编号。可用姿势不足五个时，在调用模型前提示补充素材。无合适候选、编号不存在或图片不属于所选姿势时，明确失败；不得随机补齐或绕过步骤。每个镜头展示共享背景、选定姿势、选择理由，动作说明可展开。用户可填写“姿势要求”并重新选姿势。

最终成片仍每张最多六个参考图，图 1 是冻结的统一背景，图 2 是选定姿势图，后续依次为模特、主推款和搭配款参考板。冻结动作说明注入 `runtime.shot_pose`，并追加到现有 `runtime.shot_styling`，保证已有使用造型占位符的模板能收到本轮姿势事实。管理员应使成片 Prompt 与选定姿势一致，避免同时要求忽略参考动作或任意重新设计姿势。

## Prompt 配置与启用

新增空槽位 `assembly.pose_tagging`（姿势识别）和 `assembly.pose_selection`（姿势选搭）。识别返回 `{ "name": "姿势名称", "tags": { ... } }`：`name` 去除首尾空白后须为 1–80 字，回填姿势名称；`tags` 须为非空对象，完整保存到 `ai_tags_json` 并通过 API `aiTags` 返回，不把外层 name/tags 包装存入标签。首次识别及重新识别成功时同时更新名称、标签与 READY 状态，格式错误保留原名称和旧标签；选搭仅执行 `runtime.pose_phase=shortlist`，一次模型调用记录到 attempt，`selectionMode=shortlist_only` 标记当前流程；旧 `runtime.pose_shortlist` 占位符保留为空列表，仅兼容已保存配置。

管理员在 Prompt 维护选择对应槽位，点击“填入姿势参考规则”，检查品牌分段及内容后显式保存。参考正文来自 `backend/prompt_templates/pose_tagging.txt` 与 `pose_selection.txt`，仅用于填入编辑器，不是运行时 fallback，不会自动写入数据库。没有保存配置时，上传与只读浏览可用，识别/选搭返回配置错误。选姿势要求统一背景和当前品类成片 Prompt 已配置；新任务不读取旧母版槽位。

## 状态、历史与恢复

新任务：`STYLING_READY → POSE_SELECTION_RUNNING → POSE_SELECTION_READY → FINAL_RUNNING`。失败、取消分别使用既有 FAILED / CANCELLED。手动请求先持久化状态和 attempt，再后台执行；相同任务不能重复提交。调用前、响应后和提交结果前检查取消，晚到响应不得覆盖取消状态。

- 开始选姿势时冻结本次可选库、模板配置、五镜头要求和同一背景引用；复用服装选搭冻结的商品与模特输入版本；成功时冻结每镜头姿势原图、动作、理由、名称和标签。
- 成片结果集保存 `pose_selection_id`，并复制本轮五组共享背景/独立姿势引用；补片、单张重生和继续一键成片复用冻结引用。
- 主推款变化或重新服装选搭使当前姿势选择失效。重新选姿势成功后生成新的选择，旧成片标记历史；失败保留上次有效选择供查看。
- 库条目、背景、模特或成片 Prompt 后续维护不改变已有选择。选择进行中被归档、删除或更换的候选不能作为新结果提交。
- 服务重启后的中断任务明确失败；一键成片按现有技术错误重试预算恢复，手动任务可以重新执行。
- 迁移前任务 `pose_workflow_enabled=0`，可沿用旧拍摄预设继续；用户主动选姿势后升级四步。新建任务为 1，未完成姿势选搭不能开始新的成片结果集。

## 验证边界

自动化使用临时数据库和 mock 模型，覆盖上传/浏览不触发 AI、识别与重复提交、五镜头与图片归属校验、单次初筛商品与背景输入、无二次调用、取消、归档并发、冻结引用、输入失效、历史保留、删除引用释放和中断恢复。真实姿势适配效果与最终生图质量需要另行使用业务素材验收，不由 mock 测试证明。
