# 姿势库与独立姿势选搭

## 用户流程

admin 的拍摄工作台与后台执行链路固定四阶段：导入主推款 → AI 智能选搭 → 姿势选搭 → 最终成片。一键成片按同一顺序执行。姿势选搭服务已确认造型，不重新选择商品、不生成分镜、不改写五镜头的摄影要求。

user 仅显示“导入主推款 → AI 智能选搭 → 最终成片”。生成成片自动推进后台姿势选搭，不显示独立步骤、姿势要求或参考图；在最终成片页显示“正在准备拍摄”和五个待拍摄槽位。失败/取消后继续复用已有造型与成功成片，刷新仍回到最终成片页。

姿势库仅 admin 可见和访问，沿用搭配服装库的卡片、搜索、分页、批量选择、图片资产卡、大图检查与归档管理。每个姿势包含名称、稳定业务编号、唯一一张原图、完整 AI 标签和识别状态。一张图片对应一个姿势；散图和文件夹均逐张拆成独立条目，文件夹仅用于批量选择，名称默认取图片文件名（可编辑）。详情只能替换单图，替换后状态回到待识别，已冻结的拍摄历史仍使用原图。旧版多图条目在迁移 077 中保留原图并拆分，首图保留原编号，额外图片获得独立编号；拆分条目需重新识别，历史快照不变。先保存全部条目，再提交识别，失败项可重试；页面切换保留当前浏览器会话中的草稿和已入库编号。刷新页面后已入库条目仍在库中，未上传本地文件需重新选择。

默认只展示未归档姿势，支持关键词、识别状态和归档筛选。只有未归档且 READY、有有效图片的姿势参加选搭。图片变化后回到 DRAFT，旧标签可只读查看，重新识别成功才重新参与选搭。归档不影响历史任务，彻底删除需要影响预检及名称确认；被历史选姿势或调用快照引用的图片保留，最后一个引用清除后才释放文件。

## 从 lily 采用的部分

采用 lily 的标签筛选方法，当前只保留初筛：整组调用一次，查看主推款、已选搭配原图和共享背景，结合全库标签、配饰穿法及从成片 Prompt 渲染出的逐镜头要求，直接确定五个不同姿势。取消二次精选，不发送候选姿势原图；模型不得声称已看过姿势原图或为姿势偷改商品结构、搭配。最终成片仍读取选定姿势原图。

新 Prompt 每镜头直接返回 poseCode、imageId、reason、direction。兼容已保存的旧 Prompt：若仍返回 candidateCodes，直接采用每镜头第一项，唯一图片由冻结库映射，动作说明保留该姿势标签；不重新排序、不搜索替代项、不再次调用模型。首选重复、编号无效或图片不唯一则明确失败。

ToAPIs 每次消息最多 16 张图片。初筛按商品和背景实际来源数量组装：未超限时直接发送原图，超限时把全部来源按顺序合成带编号的参考板，每板最多四张，等比缩放且不裁切，编号置于独立留白区。图片清单记录发送顺序、板内位置与原始商品编号；不截断商品图片或姿势标签，也不由代码替代模型选择姿势。原始清单和实际发送清单同时写入 attempt，参考板仅在内存中组装，不修改对象存储原图。超过参考板容量时在本地明确失败；通道发送前再次校验上限，图片超限错误不自动重试。

保留本项目的先服装后姿势顺序、固定五镜头、S3 媒体与数据库历史。没有迁入 lily 的本地目录存储、服装与姿势组合自由探索、生成后自动视觉验收或自动修图。

## 职责边界

| 输入 | 职责 |
|---|---|
| 主推款、搭配服装原图 | 商品结构和细节事实 |
| StylingPlan | 已确认商品、穿法、品牌与造型方向、品类族 |
| 统一背景图 | 共享空间、背景材质、墙地关系和照明；不限制景别与构图 |
| 姿势库原图与标签 | 客观的画面布局、可辨动作、表情、接触与受力事实 |
| 姿势选搭 Prompt + 模型 | 基于标签的五镜头初筛定选，输出每镜头选择理由和动作说明 |
| 三类成片 Prompt | 五镜头景别、机位、裁切、商品表达、镜头5双视图及安全区、成像约束 |
| 代码 | 可用范围、编号与图片归属、五镜头覆盖校验、调用、状态与冻结引用；不打审美分、不硬编码动作选择规则 |

每镜头定选一张姿势图，五个镜头必须使用不同姿势编号。可用姿势不足五个时，在调用模型前提示补充素材。无合适候选、编号不存在或图片不属于所选姿势时，明确失败；不得随机补齐或绕过步骤。admin 的每个镜头展示共享背景、选定姿势、选择理由，动作说明可展开。仅 admin 可填写“姿势要求”并重新选姿势。

最终成片每张最多14个参考图，图1是冻结的统一背景，图2是选定姿势图（按既有镜头景别预裁切），后续依次为模特首图、前四张身份宫格、主推款前六张与搭配款合计前四张；商品按冻结顺序取图。冻结动作说明注入 `runtime.shot_pose`，保留姿势描述、视图说明、身体姿态、头颈与肩、手臂与手、腰髋、腿脚、视线、表情和其他可见动作，部位不可见直接附在对应事实中。旧动作字段及其不可辨限定只读兼容，历史快照不改写；优势、风险和适配规则不进入成片 Prompt。管理员应使成片 Prompt 与选定姿势一致，避免同时要求忽略参考动作或任意重新设计姿势。

## Prompt 配置与启用

新增空槽位 `assembly.pose_tagging`（姿势识别）和 `assembly.pose_selection`（姿势选搭）。识别返回 `{ "name": "姿势名称", "tags": { ... } }`：`name` 去除首尾空白后须为 1–80 字，回填姿势名称；`tags` 须为非空对象，完整保存到 `ai_tags_json` 并通过 API `aiTags` 返回，不把外层 name/tags 包装存入标签。首次识别及重新识别成功时同时更新名称、标签与 READY 状态，格式错误保留原名称和旧标签；选搭仅执行 `runtime.pose_phase=shortlist`，一次模型调用记录到 attempt，`selectionMode=shortlist_only` 标记当前流程；旧 `runtime.pose_shortlist` 占位符保留为空列表，仅兼容已保存配置。

管理员在 Prompt 维护选择对应槽位，点击“填入姿势参考规则”，检查品牌分段及内容后显式保存。参考正文来自 `backend/prompt_templates/pose_tagging.txt` 与 `pose_selection.txt`，仅用于填入编辑器，不是运行时 fallback，不会自动写入数据库。没有保存配置时，上传与只读浏览可用，识别/选搭返回配置错误。选姿势要求统一背景和当前品类成片 Prompt 已配置；新任务不读取旧母版槽位。

## 状态、历史与恢复

新任务：`STYLING_READY → POSE_SELECTION_RUNNING → POSE_SELECTION_READY → FINAL_RUNNING`。失败、取消分别使用既有 FAILED / CANCELLED。自动流程在姿势初筛调用前因配置或素材不足失败时，也持久化失败 attempt（SHOOT_PREPARATION_FAILED），避免隐藏步骤静默退出；user 看到联系管理员的业务提示，admin 可查原始原因。手动请求先持久化状态和 attempt，再后台执行；相同任务不能重复提交。调用前、响应后和提交结果前检查取消，晚到响应不得覆盖取消状态。

- 五镜头要求只引用对应品类成片 Prompt 的「## 机位&景别」章节，按 `runtime.is_shot_1` 至 `runtime.is_shot_5` 条件展开后注入 `runtime.pose_shots`。保留朝向、景别、裁切、商品展示与遮挡、双视图和安全区；品牌、造型、商品图片与标签使用已有独立入口。代码只做章节引用与占位符展开，不概括或补写规则。
- 开始选姿势时冻结本次可选库、模板配置、五镜头要求和同一背景引用；复用服装选搭冻结的商品与模特输入版本；成功时冻结每镜头姿势原图、动作、理由、名称和标签。
- 成片结果集保存 `pose_selection_id`，并复制本轮五组共享背景/独立姿势引用；补片、单张重生和继续一键成片复用冻结引用。
- 主推款变化或重新服装选搭使当前姿势选择失效。重新选姿势成功后生成新的选择，旧成片标记历史；失败保留上次有效选择供查看。
- 库条目、背景、模特或成片 Prompt 后续维护不改变已有选择。选择进行中被归档、删除或更换的候选不能作为新结果提交。
- 服务重启后的中断任务明确失败；一键成片按现有技术错误重试预算恢复，手动任务可以重新执行。
- 迁移前任务 `pose_workflow_enabled=0`，可沿用旧拍摄预设继续；用户主动选姿势后升级四步。新建任务为 1，未完成姿势选搭不能开始新的成片结果集。

## 验证边界

自动化使用临时数据库和 mock 模型，覆盖上传/浏览不触发 AI、识别与重复提交、五镜头与图片归属校验、单次初筛商品与背景输入、无二次调用、取消、归档并发、冻结引用、输入失效、历史保留、删除引用释放和中断恢复。真实姿势适配效果与最终生图质量需要另行使用业务素材验收，不由 mock 测试证明。

## 近期使用与事实保留

候选卡保留完整标签及原有顺序，附带同品类最近最多20个其他任务各自最新成功选择的 recentUsage（次数及镜头号）；当前任务排除在统计外，重复选姿势不重复累计同一任务。快照保留该事实。Prompt 在适配程度相近时优先少用姿势，代码不评分、不随机重排、不硬排除已用项；商品、镜头、核心动作和可辨表情优先于多样性。

新识别规则同时记录具体头部、表情和不确定性；JSON 动作兼容路径保留这些字段。普通字符串不改写。修改规则不会回写旧标签，也不会重识别或修改历史冻结选择。候选原图仍不进入初筛，后续在实际可见姿势图与错误转述冲突时以可见事实为准，不能据裁切后的不可见部位反推动作不存在。

## 通用画面标签与单/多视图适配

姿势标签将三个维度分开：`画面布局` 为 `单人单视图 / 同人多视图 / 多人同框 / 多图拼接 / 无法判断`；`视图组合` 按画面顺序记录各视图朝向（例如正面、正面 + 背面、正面 + 侧面、正面 + 正面、正面 + 侧面 + 背面），保留重复朝向；`参考景别` 记录全身、半身、局部或逐视图的混合范围。三者均不等于图片宽高比。`视图说明` 仅在前三项不足以交代格位或影像关系时补充，不重复已有信息。确认同一模特同一穿着的多视图即使分格也归入同人多视图；其他独立图片拼接归入多图拼接。多视图的动作和表情按位置分别记录，不混合左右两个人物的手脚。

姿势识别参考 Prompt 要求布局、视图组合、参考景别，视图说明按需补充；JSON 标签仍完整存储，兼容管理员自定义识别规则。姿势选搭 Prompt 先核对布局：镜头1–4只选明确的单人单视图，镜头4全身不等于正背并排；镜头5优先选同人多视图中恰好正面/轻侧正 + 背面/轻侧背的一组，可在没有合适双视图时选支持正背展示的单人动作。双正面、正侧、三视图、多人同框和其他拼图不能冒充正背图；不通过横向拆图或宣称只取其中一人来绕过。布局缺失、无法判断或关键标签冲突时，Prompt 要求选择其他候选；不足五个返回明确缺口。规则由 Prompt + 模型执行，后端不做姿势审美评分、自动替换或硬编码选姿策略。

卡片优先展示布局、视图组合与参考景别，缺失布局显示待补录。admin 可在已识别素材详情看原图后补录布局、视图组合，不调用 AI、不改变 READY 状态、不补造其他动作；重新识别会覆盖整份标签，替换图片仍须重新识别。保存期间禁止修改识别中或归档条目；选搭进行中标签变化使该轮提交失败，避免冻结旧布局。历史选择和成片不回写，旧任务需要重新选姿势才采用新事实。

迁移 086 仅把与旧参考正文摘要完全一致的已保存姿势识别、姿势选搭、三类成片和提示词整理配置升级；空配置和管理员自定义正文不覆盖、不自动启用。自定义配置需在 Prompt 维护显式合并新规则。迁移不猜测旧素材标签，不触发识别，不改变历史快照。旧素材应人工补录或经明确授权重新识别。

## 可通过文字还原的客观姿势识别

识别以“仅凭文字能还原原图可见姿态、肢体关系、视线和表情”为标准，完整性优先。简洁只删除重复、空泛修饰与评价，不删减有依据且影响还原的细节，不设字数或句数上限。商品适配由选姿阶段结合实际商品与镜头判断。“姿势描述”是唯一允许少量整体主观概括的标签，用一两句概括姿态与气质，不判断人物性格、美丑、情绪成因或高级感。其余标签只写可见事实：身体姿态、头颈与肩（含脖子、下颚）、手臂与手（含肘部）、腰髋、腿脚（含膝、小腿、脚尖与接地）、视线、表情，以及按需补充的其他可见动作。分组用于完整组织各视图的观察结果；所有可见且影响还原的部位必须覆盖，分别交代方向、位置、伸屈、接触及相互关系。完全画外的分组可省略，但须在景别或相邻部位说明边界；不得为填字段猜测不可见事实。同一事实不重复，多视图分别完成整体到局部描述。

新识别不输出优势、风险、适配规则、执行条件、存疑信息、核心动作或可调整动作。插袋、持物、坐倚等直接记录可见接触；看不清的部位在对应标签中简记“被遮挡 / 画外 / 不可辨”，不另列存疑分析，不补造关节、重心或表情。画面布局、视图组合、参考景别仍是必填客观事实，与姿势描述一起保留。

迁移087兼容已保存086阶段参考正文的环境，仅按摘要精确升级姿势识别与选姿模板，自定义与空配置保留。旧素材和历史快照不批量删改；新规则在下次明确发起识别时使用，模型调用不由迁移触发。选姿Prompt忽略旧标签的评价与调整建议，仍读取其动作事实。

还原检查在原有识别调用内进行：若一段文字能对应多个明显不同的姿势，且原图能区分，应补齐消除歧义的事实。例如扶腰要分清左右手、接触点、肘部指向和可辨手指关系；错步要分清前后腿、膝、小腿、脚尖与接地；回头要区分躯干、头、视线方向。检查只改进最终标签，不输出评分或分析，不增加复核调用。选姿 direction 同样保留还原当前镜头所需的细节，不将详细标签再次压缩成笼统动作词。身份、商品、配饰外观、背景及照明仍由各自参考图负责。
