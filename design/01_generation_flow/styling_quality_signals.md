# AI Stylist 质量信号与客户审核闭环

## 1. 核心判断

智能选搭的目标不是“选出可穿且不遮挡主推款的衣服”，而是为主推款生成当前条件下最好的电商棚拍造型。系统应该尽最大努力产出可审核方案，客户审核才是最终质量裁判。

因此，审美、穿法、品牌感、配饰边界和图位问题不应作为普通用户可见的硬报错。它们应成为后台 `QualitySignal`：

- 用于 AI Stylist 自我修正和后续重新选搭。
- 用于记录本次方案的客户审核重点。
- 用于复盘 AI Stylist 是否正确比较空库内搭配、库内配角和被拒方案。
- 用于后续优化标签体系、prompt 和品牌样本库。

硬失败只保留给工程或数据层面不可继续的问题，例如素材缺失、非法候选 ID、provider 调用失败、任务状态冲突、存储不可读等。

## 2. 背景

白色高腰阔腿裤案例暴露了两个层面的问题：

- AI Stylist 为了露出裤腰，把不支持 `tucked` 的针织/开衫类上衣写成“塞进裤腰”。
- 系统识别到穿法不合理后，直接向用户报错，导致用户看到的是“智能选搭失败”，而不是一个可审核、可改进的拍摄方案。

第一点需要质量判断，第二点说明质量判断不能再作为用户可见阻断。软件层面要做的是“把当前方案做到最好并记录风险”，而不是“自我否定后让用户停在错误页”。

## 3. 质量信号

`QualitySignal` 是内部结构化记录，不等于失败。建议字段：

```json
{
  "code": "unsupported_tuck_method",
  "category": "wearing_method",
  "severity": "review",
  "message": "方案使用了搭配服装或主推款不支持的塞腰/半塞穿法，建议审核上衣下摆处理。"
}
```

阶段 1 先记录在 `StylingPlan.quality_signals`，不新增表；后续可以拆成独立表并与客户审核反馈关联。

主要信号：

| code | 含义 | 默认处理 |
|---|---|---|
| `low_critic_scores` | AI Stylist 自评分偏低 | 继续保存方案，进入客户审核重点 |
| `suspicious_full_scores` | 接近满分但缺少诊断/风险说明 | 继续保存，标记为低可信自评 |
| `missing_critic_diagnosis` | 审美诊断字段缺失 | 继续保存，后续优化 prompt |
| `template_accessory_risk` | 生成了公文包、大体量托特等模板化配饰 | 继续保存，后续修正配饰边界 |
| `unsupported_tuck_method` | 塞腰/半塞穿法缺少服饰标签支持 | 继续保存，审核重点关注下摆处理 |
| `high_waist_dark_outerwear_stack` | 高腰裤叠深色厚重外套，比例/色块风险高 | 继续保存，审核重点关注比例和色彩重量 |
| `unexplained_outerwear_conflict` | 多件外套缺少真实穿着解释 | 继续保存，审核重点关注层次关系 |

## 4. 系统行为

### 4.1 不再因为业务质量信号报错

以下问题不应让任务进入 `FAILED`：

- 审美分低。
- 穿法不自然。
- 缺少部分 Aesthetic Critic 诊断。
- 配饰模板化。
- 色块沉重、比例风险或品牌感不足。
- 搭配库缺少更好候选。

这些问题应被记录为 `quality_signals`，并保留在技术详情和生成记录复盘中。普通用户不应看到内部异常堆栈或“AI Stylist 方案未通过质量门”这类文案。

### 4.2 仍然保留硬校验

以下问题属于不可继续的工程/数据错误，仍可失败：

- AI Stylist 返回不存在或未在候选集中的服饰 ID。
- 返回重复服饰 ID 且无法规范化。
- Gemini/API/存储调用失败。
- 主推款图片缺失或素材不可读。
- 任务状态不允许进入当前阶段。
- 工程 fallback 方案试图进入生产链路。

### 4.3 最佳努力策略

当出现质量信号时，系统应按阶段逐步增强自动修正能力：

1. 阶段 1：不中断流程，记录 `quality_signals`，继续产出当前最佳方案。
2. 阶段 2：若选中方案有高风险，优先从 AI Stylist 的其它 `outfit_candidates` 中选择更低风险方案。
3. 阶段 3：自动改写可修复穿法，例如把不支持全塞的上衣改成自然下摆、短款露腰头、敞开外搭或空库内搭配。
4. 阶段 4：客户审核反馈回流，影响候选排序、品牌样本、穿法标签和 prompt。

## 5. 客户审核闭环

客户审核是最终质量判定。审核入口应面向业务语言：

- 搭配不好看。
- 穿法不自然。
- 不符合 Lily。
- 主推款不突出。
- 图位/姿势不理想。
- 搭配库没有合适配角。

这些反馈应回流到：

- `StylingPlan` 候选比较：判断是否应选择空库内搭配、是否错选库内配角。
- Prompt：调整类别、颜色、材质、季节、遮挡风险和空库内搭配优先级。
- 标签体系：补充穿法能力、禁忌和体量风险。
- 品牌样本库：增加 Lily 官方或客户确认样本。
- AI Stylist prompt：强化真实穿法、配饰边界和主推款优先。

## 6. 结论

新版 AI Stylist 的质量机制不是一道让用户停下来的门，而是一组持续改进的信号：

```text
软件尽力产出当前条件下最好的方案；
客户审核决定方案是否可用；
审核结果回流优化流程，而不是让普通用户面对内部报错。
```
