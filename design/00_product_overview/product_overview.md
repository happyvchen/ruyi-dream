# 产品总览

## 一句话定义

Lily AI 模特组图生成工具，是一个面向 Lily 内部电商图片生产的 MVP 工具。用户上传或选择一个服装货号图包，系统为该货号保存默认组图方案，再基于默认方案自动生成一组可用于淘宝、天猫主图场景的模特服装展示图。

这里的“自动生成”不是把所有信息直接交给 Image 2。产品内部应先完成素材预处理和组图策划，再由 Image 2 逐张生成。

## 当前不做什么

当前项目不做标准 SaaS，不考虑多客户、多品牌空间、团队权限、计费、模板市场、API 开放平台等能力。

当前项目也暂不做：

- 自动质量检测
- 大规模风格模板
- 自然风景、街拍、办公室等复杂场景
- 视频生成
- 全链路商品详情页设计
- ZIP 上传
- 素材图片角色识别

## 目标用户

当前目标用户是 Lily 内部或服务 Lily 的运营、视觉、商品、AI 生图执行人员。

他们的核心诉求不是自由创作，而是：

- 快速把一个服装货号变成一套模特图
- 尽量接近 Lily 既有棚拍成片质感
- 尽量减少人工 prompt 编写和反复试错
- 支持单张不满意时重生
- 输出后可直接进入电商上传或后期精修流程

他们也不应该被要求理解 AI 生成内部机制。前台 UI 应该围绕 `拍摄任务` 展开，而不是围绕 prompt、任务包、模型输入职责展开。

## 核心入口

主生产入口：

`生成组图`

必要辅助入口：

- `服装素材`：上传与管理货号图包、查看识别结果、生成/更新默认组图方案
- `数字模特`：维护数字模特列表、头部素材和身体参数；当前阶段先维护 1 个默认数字模特
- `品牌调性模板`：维护 Lily 历史真实图沉淀出的风格、Pose、鞋包、背景、构图边界；普通用户日常可弱化或隐藏

## 核心工作流

1. 用户进入 `服装素材`
2. 上传散图或文件夹，形成本地预览图包
3. 用户编辑货号/标题、删除图片，保存上传
4. 系统生成或更新该货号默认组图方案
5. 用户进入 `生成组图`
6. 选择货号，系统读取默认组图方案
7. Image 2 逐张生成
8. 用户对单张图重生或确认
9. 导出最终主图

前台默认路径应尽量短：

```text
上传/选择服装 -> 保存默认组图方案 -> 生成/确认/导出
```

## 技术分工

| 模块 | 职责 |
| --- | --- |
| 预处理层 | 识别服装事实、维护数字模特档案、初始化 Lily 品牌模板 |
| 策划层 | 选择品类规则、Pose、鞋包边界、镜头取景，生成单张任务包 |
| Image 2 生成层 | 根据图片、参数、模板和短文本逐张生成图片 |
| 人工确认层 | 单张确认、重生、导出 |

## 产品判断

这个工具不应该把用户训练成 prompt 工程师。

前台产品语言应该是摄影和电商语言：

- 全身
- 半身
- 背面
- 侧身
- 局部
- 领口
- 袖口
- 腰头
- 裤脚
- 裙摆
- 白底棚拍
- 浅灰棚拍

底层可以使用 prompt 和多图参考，但用户主要面对的是结构化选择与确认。

prompt 不是核心产品入口。核心产品入口是 `商品事实卡`、`数字模特档案`、`品牌调性模板`、`组图方案` 和 `单张生成任务包`。

但这些核心能力不等于都要暴露给普通用户。普通用户看到的是：

- 服装摘要
- 默认组图方案
- Lily 风格摘要
- 结果和重生操作

系统内部处理：

- 商品事实卡
- 品牌模板命中
- Pose 模板匹配
- 单张生成任务包
- Image 2 prompt

## 成功标准

MVP 阶段的成功不以功能完整度衡量，而以能否稳定完成以下任务衡量：

> 选择一个 Lily 服装货号图包和一个数字模特，生成 5 张左右风格统一、商品清晰、构图接近 Lily 历史成片的电商主图。

如果 Lily 认为其中部分图片可进入实际使用或轻后期使用，则 MVP 成立。
