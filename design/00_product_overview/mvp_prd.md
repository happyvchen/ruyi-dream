# MVP PRD

## 1. 项目目标

为 Lily 建立一个内部 AI 模特组图生成工具。用户选择一个数字模特和一个服装货号图包后，系统自动识别服装信息，结合 Lily 默认棚拍风格，生成一套电商主图。

MVP 的关键不是开放一个复杂 prompt 输入框，而是建立 `预处理层 -> 组图策划层 -> Image 2 生成层` 的生产链路。

同时，MVP 的前台 UI 不应该把这条链路全部暴露出来。普通用户只需要看到拍摄任务：选择服装、选择模特、确认组图、生成结果。

## 2. MVP 范围

### 包含

- 单一主入口：生成组图
- 支持多数字模特管理与选择
- 当前阶段先维护 1 个默认数字模特
- 服装货号图包上传或选择
- 服装基础识别结果展示与人工修正
- 数字模特身份锁定
- Lily Pose 模板选择
- Lily 品牌调性模板库
- 前置组图策划器
- 单张生成任务包
- 基于真实参考图的鞋履/配饰 Styling 边界
- 服装穿着比例约束
- 按服装品类自动生成组图方案
- 生成一组图，默认 5 张
- 支持单张重生
- 支持最终图导出

### 不包含

- 自动质量检测
- 多客户 SaaS 能力
- 复杂角色权限
- 计费和套餐
- 模板市场
- 大量场景风格
- 视频生成

## 3. 信息架构

### 3.1 生成组图

核心生产页面。

默认功能：

- 选择数字模特，默认选中当前已维护模特
- 选择服装货号
- 查看系统识别摘要
- 查看 Lily 默认风格摘要
- 查看并确认组图方案
- 触发生成
- 查看生成结果
- 单张重生
- 导出最终图片

默认不展示：

- prompt
- Image 2 任务包
- 前置组图策划器
- 图片职责拆分
- Pose 模板 ID
- 品牌参考图 ID

这些可以作为内部调试信息或高级模式，而不是普通用户主界面。

### 3.2 服装素材

用于管理当前可用服装图包。

功能：

- 查看货号列表
- 查看每个货号下的图片
- 标记正面图、背面图、细节图、颜色图
- 查看系统识别出的品类、颜色、面料、结构

MVP 可先不做复杂上传管理，只要支持读取指定目录和手动选择货号即可。

### 3.3 数字模特

用于维护数字模特资产。

功能：

- 查看模特列表
- 新增或编辑数字模特
- 查看头部图包
- 查看模特基础参数
- 修改默认身体参数
- 修改默认风格约束
- 维护各拍摄角度对应的头部参考图

当前阶段只维护 1 个默认数字模特，但产品结构需要保留多模特能力，避免后续新增模特时重构主流程。

### 3.4 品牌调性模板

用于维护 Lily 历史真实图沉淀出的生产模板。

功能：

- 查看默认 Lily 品牌模板
- 查看按品类拆分的子模板
- 查看模板关联的真实参考图
- 维护 Pose、鞋包、背景、光线、构图边界
- 支持品牌初始化或模板修改时重新分析真实图

MVP 阶段可以先内置默认模板，不需要做复杂模板市场或多品牌管理。

### 3.5 组图策划器

这是系统内部模块，不一定需要独立页面。

功能：

- 根据服装事实卡判断品类和风险点
- 根据品类选择默认组图结构
- 从品牌模板库检索同品类真实参考图
- 为每张图绑定 Pose、头部角度、镜头范围和 Styling 边界
- 生成每张图的单张生成任务包

组图策划器可以由推理模型、规则引擎和模板检索共同实现。它负责做判断，Image 2 负责按判断生成。

## 4. 生成组图页面

推荐页面结构：

顶部：页面标题

- 生成组图
- 选择服装和模特，确认组图后即可生成电商主图

主体：三步任务流

第一步：选择服装

- 当前货号
- 服装主缩略图
- 系统识别摘要
- 更换服装
- 识别结果折叠区

第二步：选择模特

- 当前数字模特
- 模特头像
- 模特标签
- 更换模特

第三步：确认组图方案

- 默认 5 张图位
- Lily 默认棚拍风格摘要
- 高级设置折叠区

操作区：

- 生成组图
- 预览方案
- 预计生成 5 张，可单张重生

结果区：

- 生成结果网格
- 单张重生
- 设为最终图
- 导出

## 5. 用户可编辑字段

MVP 阶段默认开放必要字段：

- 服装货号
- 数字模特：默认当前已维护模特
- 组图方案：默认按品类生成
- 补充要求：可选

高级设置中开放：

- 品类
- 版型：修身 / 标准 / 宽松
- 面料感觉：挺括 / 垂坠 / 柔软 / 厚实 / 轻薄
- 模特穿着尺码：默认 M
- 穿着长度：膝上偏短 / 膝上中段 / 及膝 / 过膝
- 廓形宽度：直筒 / 轻 A 字 / 大 A 字 / 伞摆
- 下摆露出：窄 / 标准 / 宽
- 背景：白色 / 浅灰
- 构图倾向：全身偏多 / 半身偏多 / 平衡
- Styling 自由度：低 / 标准 / 高，默认标准

不建议 MVP 阶段开放复杂 prompt 文本框作为主交互。

可以保留一个 `补充要求` 字段，但应作为辅助，而不是核心入口。

用户修改结果时，也不应该直接改 prompt，而是选择业务原因：

- 姿势不合适
- 模特不像
- 服装不准确
- 搭配不合适
- 构图不合适
- 其他补充

系统再把这些原因映射到 Pose、身份、服装事实、品牌模板或镜头任务。

## 5.1 系统内部字段

这些字段不一定直接暴露给用户，但应进入生成链路：

- 商品事实卡
- 商品风险点
- 品牌模板 ID
- 品类子模板 ID
- 真实参考图 ID 列表
- Pose 模板 ID
- 单张图位 ID
- 单张生成任务包
- 已确认图 ID
- Image 2 短 prompt

## 6. 默认风格

默认风格为：

`Lily 白/浅灰棚拍风格`

风格描述：

- 干净浅色背景
- 柔和棚拍光
- 电商主图构图
- 都市通勤感
- 商品优先
- 模特自然、克制、轻熟
- 不做夸张时装大片
- 不做复杂外景

## 7. 输出规格

MVP 默认输出：

- 1:1 主图
- 建议 1200x1200 或 2000x2000
- 每个货号默认 5 张

后续可扩展：

- 3:4 竖版
- 详情页长图
- 白底商品图
- 局部细节图

## 8. 成功标准

一个货号完成生成后，应满足：

- 同一组图中模特脸和发型稳定
- 服装颜色接近原始服装图
- 服装结构没有明显变款
- 构图接近 Lily 历史主图
- 至少有 2-3 张图具备实际可用或轻后期可用价值

## 9. 关键技术边界

- Image 2 只负责最终图片生成。
- 品牌调性不在每次生图时重新推理，而是在品牌初始化或模板修改时推理并沉淀。
- 鞋包、Pose、镜头取景由组图策划器和品牌模板库决定。
- 服装事实以图片为准，文本只做任务说明和禁止项。
- 尺寸比例问题优先通过可选尺寸参数解决，不能只靠 prompt。
