# MVP PRD

## 1. 项目目标

建立一个内部 AI 模特组图生成工具。用户选择一个数字模特和一个服装货号图包后，系统自动识别服装信息，结合 默认棚拍风格，生成一套电商主图。

MVP 的关键不是开放一个复杂 prompt 输入框，而是建立 `预处理层 -> 组图策划层 -> Image 2 生成层` 的生产链路。

同时，MVP 的前台 UI 不应该把这条链路全部暴露出来。普通用户只需要看到拍摄任务：维护服装素材和默认组图方案，进入生成页后选择货号并直接生成结果。

## 2. MVP 范围

### 包含

- 主生产入口：生成组图
- 素材准备入口：服装素材
- 支持多数字模特管理与选择
- 当前阶段先维护 1 个默认数字模特
- 服装货号图包上传、预览、编辑、保存
- 服装基础识别结果展示与人工修正
- 数字模特身份锁定
- Pose 模板选择
- 品牌调性模板库
- 前置组图策划器
- 单张生成任务包
- 基于真实参考图的鞋履/配饰 Styling 边界
- 服装穿着比例约束
- 按服装品类自动生成默认组图方案，并保存到货号下
- 生成一组图，默认 5 张
- 支持单张重生
- 支持任务级生成记录：每次整组生成一条记录，单张重生收纳在对应图位记录内
- 支持从历史任务恢复到生成组图页查看和继续操作
- 支持前端深链接：Tab、货号、模特、生成任务可通过 URL 直接定位
- 支持最终图导出

### 不包含

- 自动质量检测
- 多客户 SaaS 能力
- 复杂角色权限
- 计费和套餐
- 模板市场
- 大量场景风格
- 视频生成

## 3. 信息架构

### 3.1 生成组图

最终生成页面。该页面不再承担方案策划职责，而是读取服装素材页保存的默认组图方案。

默认功能：

- 选择服装货号
- 查看系统识别摘要
- 查看该货号是否已有默认组图方案
- 直接触发生成
- 查看生成结果
- 单张重生
- 导出最终图片
- 查看最近生成任务概览
- 点击生成任务概览后，在当前页面恢复并展示该历史任务的输入和结果

默认不展示：

- prompt
- Image 2 任务包
- 前置组图策划器
- 图片职责拆分
- Pose 模板 ID
- 品牌参考图 ID

这些可以作为内部调试信息或高级模式，而不是普通用户主界面。

生成组图页右侧保留“生成记录”概览区。该区域不是系统事件日志，而是任务级历史入口：

- 优先展示当前货号相关的最近生成任务。
- 每条记录展示缩略图、货号、状态、完成张数、记录号和重生次数。
- 点击记录时，效果等同于“恢复到生成页”：仍停留在生成组图页，加载该历史任务对应的 SKU、组图方案和生成结果。
- 若用户需要查看完整入参、图位 attempts 和调试 JSON，可进入独立“生成记录”页。

### 3.2 服装素材

用于管理当前可用服装图包。

功能：

- 查看货号列表
- 查看每个货号下的图片
- 上传 N 张散图并填写货号，对应一个图包
- 上传一个文件夹，默认货号为文件夹名并支持修改
- 上传 N 个文件夹，默认生成 N 个图包并支持逐个修改货号
- 上传前进入“预览与编辑”，支持修改货号/标题、删除图片
- 保存上传后生成或更新默认组图方案
- 查看系统识别出的品类、颜色、面料、结构
- 管理素材图片：追加图片、删除图片；默认第一张图片作为封面

MVP 暂不支持 ZIP 上传，也不做素材图片类型识别。图片卡片统一展示文件名、尺寸、大小，不展示“主参考/参考图/3D 图”等角色标签。

素材保存后，后端将图片写入 S3 兼容对象存储，前端读取后端返回的短期预签名 URL。当前阶段不引入 CDN，也不设计并行存储业务分支。

### 3.3 数字模特

用于维护数字模特资产。

功能：

- 查看模特列表
- 新增或编辑数字模特
- 在同一页同时编辑基础档案与头像素材，最后统一保存
- 查看模特基础参数：身高、体重、身型、胸围、腰围、臀围、其它信息
- 维护默认模特标记
- 上传一张或多张头像，上传后再逐张设置角度
- 支持头像替换、删除、拖拽排序
- 支持头像先处于“未设置”状态，后续再分配角度
- 维护各拍摄角度对应的头部参考图，并允许存在未分配角度的临时头像

当前阶段只维护 1 个默认数字模特，但产品结构需要保留多模特能力，避免后续新增模特时重构主流程。

### 3.4 品牌调性模板

用于维护 品牌历史真实图沉淀出的生产模板。

功能：

- 查看默认 目标品牌模板
- 查看按品类拆分的子模板
- 查看模板关联的真实参考图
- 维护 Pose、鞋包、背景、光线、构图边界
- 支持品牌初始化或模板修改时重新分析真实图

MVP 阶段可以先内置默认模板，不需要做复杂模板市场或多品牌管理。

### 3.5 组图策划器

这是系统内部模块，不一定需要独立页面。

功能：

- 根据服装事实卡判断品类和风险点
- 根据品类选择默认组图结构
- 从品牌模板库检索同品类真实参考图
- 为每张图绑定 Pose、头部角度、镜头范围和 Styling 边界
- 生成每张图的单张生成任务包

组图策划器可以由推理模型、规则引擎和模板检索共同实现。它负责做判断，Image 2 负责按判断生成。

### 3.6 生成记录

用于查看、复盘和恢复历史生成任务。

主粒度：

- 每次用户点击“生成组图”并创建整组生成任务，形成一条 `GenerationRun`。
- 同一个素材包重复生成一次，形成新的 `GenerationRun`。
- 单张重生不新增 `GenerationRun`，也不新增一条前台历史任务；它追加到对应 `GenerationImage.attempts_json`。

列表展示：

- 货号和标题
- 创建时间
- 任务状态
- 完成张数 / 总图位数
- 最终图数量
- 重生次数
- 缩略图预览
- 操作：查看详情、恢复

详情展示：

- 任务概览：记录号、货号、状态、创建时间、图位数、调用次数、最终图数、方案号
- 本次入参快照：货号、模特、品牌模板、商品摘要
- 输出与重生过程：每个图位当前输出、状态、prompt 快照、attempt 列表
- 高级调试：`taskPackage`、`providerRequest`、`providerResponse`

生成记录页不是事件日志页。`event_logs` 仍保留用于排查，但前台默认不把事件流水作为主记录展示。

## 4. 生成组图页面

当前页面结构：

顶部：页面标题

- 生成组图
- 选择服装货号，直接使用默认组图方案生成电商主图

主体：两步任务流

第一步：选择服装

- 当前货号
- 服装主缩略图
- 系统识别摘要
- 选择货号
- 识别结果折叠区

第二步：使用默认方案

- 默认棚拍风格摘要
- 默认方案绑定的数字模特
- 默认 5 张图位数量
- 若缺少默认方案，则提示去服装素材页生成/更新

操作区：

- 生成组图
- 直接使用默认方案，可单张重生

结果区：

- 生成结果网格
- 单张重生
- 设为最终图
- 导出

右侧记录区：

- 生成任务概览卡
- 显示最近任务的缩略图和完成状态
- 点击后直接在生成组图页恢复该历史任务

## 5. 用户可编辑字段

MVP 阶段默认开放必要字段：

- 服装货号
- 数字模特基础档案：`modelId`、名称、身高、体重、身型、胸围、腰围、臀围、其它信息、默认模特
- 数字模特头像：逐张上传、分配角度、替换、删除、排序
- 组图方案：默认按品类生成
- 补充要求：可选

高级设置中开放：

- 品类
- 版型：修身 / 标准 / 宽松
- 面料感觉：挺括 / 垂坠 / 柔软 / 厚实 / 轻薄
- 模特穿着尺码：默认 M
- 穿着长度：膝上偏短 / 膝上中段 / 及膝 / 过膝
- 廓形宽度：直筒 / 轻 A 字 / 大 A 字 / 伞摆
- 下摆露出：窄 / 标准 / 宽
- 背景：白色 / 浅灰
- 构图倾向：全身偏多 / 半身偏多 / 平衡
- Styling 自由度：低 / 标准 / 高，默认标准

不建议 MVP 阶段开放复杂 prompt 文本框作为主交互。

可以保留一个 `补充要求` 字段，但应作为辅助，而不是核心入口。

用户修改结果时，也不应该直接改 prompt，而是选择业务原因：

- 姿势不合适
- 模特不像
- 服装不准确
- 搭配不合适
- 构图不合适
- 其他补充

系统再把这些原因映射到 Pose、身份、服装事实、品牌模板或镜头任务。

## 5.1 系统内部字段

这些字段不一定直接暴露给用户，但应进入生成链路：

- 商品事实卡
- 商品风险点
- 品牌模板 ID
- 品类子模板 ID
- 真实参考图 ID 列表
- Pose 模板 ID
- 单张图位 ID
- 单张生成任务包
- 已确认图 ID
- Image 2 短 prompt

## 6. 默认风格

默认风格为：

`白/浅灰棚拍风格`

风格描述：

- 干净浅色背景
- 柔和棚拍光
- 电商主图构图
- 都市通勤感
- 商品优先
- 模特自然、克制、轻熟
- 不做夸张时装大片
- 不做复杂外景

## 7. 输出规格

MVP 默认输出：

- 1:1 主图
- 建议 1200x1200 或 2000x2000
- 每个货号默认 5 张

后续可扩展：

- 3:4 竖版
- 详情页长图
- 白底商品图
- 局部细节图

## 8. 成功标准

一个货号完成生成后，应满足：

- 同一组图中模特脸和发型稳定
- 服装颜色接近原始服装图
- 服装结构没有明显变款
- 服装素材页可以稳定生成和更新默认组图方案
- 数字模特页可以稳定维护未设置头像并在后续补充角度
- 构图接近目标品牌 历史主图
- 至少有 2-3 张图具备实际可用或轻后期可用价值

## 9. 前端 URL 与深链接

MVP 前端虽然是 React 单页应用，但 URL 应表达用户当前可恢复的位置。

当前路由约定：

```text
/generate
/generate?sku=125329C0908714
/generate?run=7
/garment-skus
/garment-skus/125329C0908714
/model-profiles
/model-profiles/Face-01
/generation-runs
/generation-runs/7
```

语义：

- `/generate`：生成组图工作台。
- `/generate?sku={sku}`：进入生成组图页，并选中指定货号。
- `/generate?run={runId}`：进入生成组图页，并恢复指定历史任务的输入和结果。
- `/garment-skus/{sku}`：进入服装素材页并打开指定货号图包。
- `/model-profiles/{modelId}`：进入数字模特页并打开指定模特。
- `/generation-runs/{runId}`：进入生成记录页并打开指定任务详情。

设计原则：

- SKU 使用业务货号作为 URL 标识。
- 数字模特使用 `modelId` 作为 URL 标识。
- 生成任务使用系统记录号 `runId`。
- 弹窗、折叠面板、hover、临时表单草稿不进入 URL。
- URL 不暴露后端数据库表名以外的内部实现细节，也不暴露 provider request id。

## 10. 关键技术边界

- Image 2 只负责最终图片生成。
- 品牌调性不在每次生图时重新推理，而是在品牌初始化或模板修改时推理并沉淀。
- 鞋包、Pose、镜头取景由组图策划器和品牌模板库决定。
- 服装事实以图片为准，文本只做任务说明和禁止项。
- 尺寸比例问题优先通过可选尺寸参数解决，不能只靠 prompt。
