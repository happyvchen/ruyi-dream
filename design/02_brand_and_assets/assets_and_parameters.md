# 素材与参数

## 媒体资产

所有导入图片统一入 `media_assets`，对象存储使用 S3 兼容接口。后端生成 `thumb` 和 `preview` 派生图用于列表和弹窗，AI 输入和下载保留原图。

前端所有图片维护与查看统一复用图片资产卡和大图检查器：卡片只读取 `thumb`，详情展示读取 `preview`，用户点击后才读取 `original`；追加、替换、删除、拖动排序和下载作为场景能力配置，不另造页面专用图片 UI。

媒体对象 key 按不可变资源处理：已登记的 `object_key`、`thumb_key` 和 `preview_key` 不得被不同图片内容覆盖。替换、重新导入、重新生成、重新派生图片时必须生成新 key 并更新数据库引用；只有明确删除且引用计数为 0 的媒体才释放对象存储文件。该约束是浏览器 HTTP 缓存成立的前提，避免用户因缓存看到旧图。

`搭配服装库` 每套最多维护 6 张纯服装参考图，`AI 摄影棚` 每个主推款最多维护 8 张参考图。Gemini 在当前业务图片包内挑选并排序；图片未达上限时允许从列表末尾的统一加号卡继续添加。

## 导入归组规则

`AI 摄影棚` 主推款和 `搭配服装库` 导入共用同一套用户心智：用户选择散图、一个货号文件夹、一个包含多个货号的上级文件夹，或拖入多个货号文件夹；系统在创建前展示可编辑的待导入清单。

- 散图合并为一套，货号 / 任务名默认为待填写，用户提交前需要确认。
- 一个直接包含图片的文件夹作为一套，文件夹名作为货号 / 任务名。
- 一个上级文件夹下存在多级目录时，系统递归扫描，凡是直接包含图片且其子目录不再包含图片的最底层图片目录，作为一套，目录名作为货号 / 任务名。
- 不提供“选择 N 个文件夹”的文件选择器能力；如需一次处理多个货号，用户选择一个上级文件夹，或拖入多个货号文件夹。
- 如果某个目录自己有图片，子目录里也有图片，视为混合结构；前台必须在待导入清单中标记异常，由用户确认拆分或调整，不应静默猜测。
- 非图片文件不进入图片包；前台应提示已忽略的非图片文件数量。
- 待导入清单允许继续添加，每次添加仍按同一规则归组并追加到清单。
- `AI 摄影棚` 顶部 `选择图片` 用散图新建一款待创建项，顶部 `选择文件夹` 按文件夹识别并新增待创建项；补充当前货号图片只能通过卡片内部 `新增图片`。顶部入口不承担“追加到当前货号”的语义。
- 一旦创建为 `GenerationTask` 或 `StylingGarment`，不再提供继续添加文件夹并拆成新套的能力；当前对象未达 8/6 张上限时可补充图片，如需新增货号则回到导入入口重新创建。
- 暂存和已保存阶段使用同一上限：搭配服装 6 张、主推款 8 张；达到上限后不再显示末尾加号卡。

## 主推款

主推款图片挂在 `generation_task_images`。进入 AI 阶段时创建 `generation_task_input_versions`，冻结当前图片顺序、任务名和默认数字模特快照。

AI 摄影棚主推款最多取 8 张作为 Gemini 输入。点击 `AI 智能选搭` 时，Gemini 必须在同一次调用中完成主推款图片挑选/排序与 `styling_plan` 输出；后端保存 Gemini 返回的 `selected_files` 作为本次主推款输入版本的推荐参考图顺序，并保存完整 request / response 快照用于追溯。

## 搭配服装

搭配服装挂在 `styling_garments` / `styling_garment_images`。Gemini 打标只负责把图片转成可追溯标签事实；AI 智能选搭读取 READY 且未归档的搭配服装标签事实。

搭配服装库必须采用一次 Gemini 调用完成图片挑选/排序与 AI 打标。Gemini 返回仅要求包含：

```json
{
  "selected_files": ["front.jpg", "back.jpg", "fabric.jpg"],
  "ai_tags": {}
}
```

`selected_files` 按推荐入库/参考顺序排列，文件标识可以是后端提供的稳定临时文件名、导入项 id 或二者组合；原则是简洁、唯一、便于后端映射。搭配服装库只接受纯服装参考图，不接受带人物、模特、上身展示或穿搭场景图进入正式 6 张图片包。后端只接受当前请求中真实存在的文件标识，不做失败兜底：Gemini 连接/读取/网关等瞬时错误由 provider 层自动重发；JSON 不可解析、缺少 `selected_files` / `ai_tags` 或引用不存在文件由编排层自动纠错重问。两类默认均最多重试 10 次，采用 `30/60/120/240` 秒封顶退避，耗尽后本次打标才失败；`selected_files=[]` 属于明确未通过导入要求，不自动重试。

搭配服装库的筛选枚举必须从事实数据派生，不在前端或后端写死固定选项。后端可基于 `ai_tags_json`、`effective_tags_json`、`manual_business_tags_json`、`official_title_tags_json` 和服装状态聚合当前可用的品类、颜色、季节、系列、渠道、上新批次、复核状态等选项，并返回计数。标签 schema 变化或品牌新增业务标签时，旧数据仍完整保留，筛选项随实际数据自然变化。

导入时间、更新时间和打标时间分别服务不同查询意图：导入时间用于定位最近入库批次，更新时间用于定位最近维护的素材，打标时间用于排查识别结果 freshness。列表排序应支持这些时间字段的正序和倒序；顶层业务对象列表默认使用首次导入时间倒序，更新时间和打标时间仅作为用户主动选择的查询视角。

## 数字模特

数字模特参考图是人物身份事实源。五张成片必须保持同一人、脸型、五官、头型、发长、发型轮廓、刘海/碎发形态、肤色、气质和身体比例。Prompt、姿势参考或 provider 默认审美不得覆盖这些事实。

## 统一背景与姿势维护

模特与背景维护一张整组背景，提供共享环境和光线；姿势库每个条目仅一张图，提供动作和表现。五镜头景别、机位、裁切及安全区由三类成片 Prompt 负责。姿势选搭时冻结背景、五个不同姿势、商品/模特输入版本与成片规则；创建结果集时复用。更换当前图片不能影响已有选择、继续生成、单张重生或历史复盘。旧预设与旧结果保留兼容。

## Image-2 输入角色

- `model_identity`
- `hero_garment`
- `styling_garment`
- `shot_background`
- `shot_pose`

参考图图号由代码按输入顺序渲染，职能解释写在 Prompt 维护模板正文。当前 ToAPIs 实际上游最多接收 6 张 `image_urls`；第一张固定为整组共享背景，仅提供环境与光线，不传 `mask_url`。模特、主推款和搭配款的多张原图由后端分别合成角色参考板。

## 当前生成参数

- 最终成片：五个固定镜头分别生成 1:1、2K、high 单图。
- 每镜头固定输入共享背景、姿势、模特身份参考板、两块主推款参考板和搭配款参考板，最多 6 个 URL；不使用同组成片连续性锚点。
- 五镜头共用背景与光线，使用不同姿势参考；人物位置、尺度、景别与裁切由各镜头 Prompt 控制。

## 配饰

鞋、包、首饰不进入搭配服装库。它们可以作为低存在感风格辅助出现在 Prompt 和生成图中，但不得遮挡主推款，不做商品级验收对象。
